# yy-skill-to-prompt

## 描述

专业的【技能转系统提示词工具】，将技能文件内容转换为完整、可直接使用的系统提示词。

## 使用场景

- 用户提供技能文件内容（SKILL.md、YAML、Markdown、指令逻辑），要求还原成系统提示词时
- 需要从现有技能中提取出完整的执行指令作为系统 Prompt 时
- 需要理解现有技能的完整逻辑并整理成可直接复用的系统提示词时

不应触发：

- 用户要求创建全新技能而非逆向解析现有技能时
- 用户要求修改现有技能而非提取系统提示词时
- 输入不是技能内容而是普通代码或文档时

## 指令

### 步骤 1. 完整理解输入技能

完整理解输入技能的功能、流程、逻辑、约束、输出格式、角色定位。

### 步骤 2. 提取关键信息并分类

提取原始技能中的关键信息并分类到 7 大章节结构中。

**7 大章节结构映射：**

从原始技能文件中**按内容语义（而非区块名称）**提取并分类到以下 7 大章节：

| 目标章节             | 应提取的内容类型                                           |
| -------------------- | ---------------------------------------------------------- |
| 头部                 | 技能身份定位、主要职责、明确声明不做的事                   |
| 1. 🎯 适用场景       | 触发条件、何时使用、何时不使用、支持的文件/项目类型        |
| 2. ⚙️ 执行逻辑与步骤 | 工作流阶段、操作流程、检查维度、输出格式模板、后续判断逻辑 |
| 3. 📜 核心通用规范   | 代码风格、命名规则、格式要求、技术标准（如 BEM/缩进/引号） |
| 4. 🛡️ 安全与限制     | 明确禁止的动作、数据操作限制、安全红线、目录范围限制       |
| 5. 🟢 推荐实践       | 推荐做法、注意事项、不推荐项但有合理例外的情况             |
| 6. 📝 输出规则       | 输出格式、语气要求、必须/禁止包含的输出元素                |
| 7. 🚀 对话开场白     | 用户交互入口话术、引导语                                   |

> **关键原则**：同一原始区块的内容可能拆分到多个目标章节。例如 "关键约束" 中关于代码风格的内容归入第 3 章，关于禁止操作的内容归入第 4 章。

### 步骤 3. 合并生成系统提示词

将所有内容合并成一段流畅、专业、可直接使用的完整系统提示词。

### 步骤 4. 严格遵循输出结构

严格遵循输出结构，不添加任何多余解释。

### 步骤 5. 创建 prompts 文件

**决策分支**：

- **技能位于当前仓库内**：在技能对应的目录中创建 `prompts/skill-prompts.md` 文件（若 `prompts/` 目录不存在则先创建），将逆向解析得到的**完整系统提示词**写入该文件，供后续直接调用
- **技能为外部提供（不在当前仓库）**：跳过文件生成，仅输出解析结果

**文件路径说明：**

- 文件路径：`<技能目录>/prompts/skill-prompts.md`
- 示例：解析 `skills/yy-comment/SKILL.md` → 生成 `skills/yy-comment/prompts/skill-prompts.md`
- 文件内容：完整的 7 章节结构化系统提示词，包含标题、角色头部、各章节、对话开场白

### 步骤 6. 内容完整性核查

反复核查原始技能文件与生成的 `prompts/skill-prompts.md` 文件的内容差异，确保 prompts 文件**完整包含**原始技能文件的所有核心内容（功能、流程、逻辑、约束、输出规则、角色定位等），无遗漏、无删减。

**核查流程：**

- 读取原始技能文件的全部内容，逐段核对
- 读取生成的 `prompts/skill-prompts.md` 文件内容
- 逐项核查：角色定位、核心任务、边界限制、适用场景、所有执行步骤、输出规则、约束条件、禁止事项、对话开场白等是否完整包含
- 若发现遗漏：补充完善 prompts 文件，直至覆盖原始技能的全部核心内容
- 核查通过标准：prompts 文件内容 ≥ 原始技能文件的核心信息，不允许出现信息丢失

## 输出格式

输出必须严格遵循以下结构，不要多余解释：

```markdown
# {skill-name} 系统提示词

- **角色**：{技能角色定位}
- **核心任务**：{核心任务描述}
- **边界**：{边界与禁止事项}

---

## 1. 🎯 适用场景

{使用场景列表}

{支持文件类型表格（如有）}

---

## 2. ⚙️ 执行逻辑与步骤

{阶段一：获取目标 + 终止条件}
{阶段二：多维/模块执行 + 规则描述}
{阶段三：输出结果格式}
{阶段四：后续判断}

---

## 3. 📜 核心通用规范

| 类型                     | 规范       | 示例   |
| ------------------------ | ---------- | ------ |
| {代码风格/命名规范/其他} | {具体规范} | {示例} |

---

## 4. 🛡️ 安全与限制（绝对禁止）

{重要声明}

| 禁止项     | 说明       |
| ---------- | ---------- |
| {禁止行为} | {具体说明} |

---

## 5. 🟢 推荐实践与注意事项

- {推荐条目 1}
- {推荐条目 2}

---

## 6. 📝 输出规则

- 格式：{格式要求}
- 语气：{语气要求}
- 约束：{其他约束}

---

## 7. 🚀 对话开场白

**用户未指定文件时：**
{开场白内容}

**用户指定了文件或文件夹时：**
{开场白内容}
```

### 规则

- 不添加、不删减、不脑补技能原本没有的逻辑
- 保持专业、简洁、可直接复用
- 只输出解析结果，不闲聊、不解释
- 原始技能中不存在的章节（如无对话开场白），可跳过该章节但在结构中保留占位提示

## 示例

**输入：**

SKILL.md 内容：

> 你是一个代码审核助手，检查代码中的错误和安全问题。先检查语法，再检查逻辑，最后输出问题列表。

**输出：**

生成 `skills/yy-code-review/prompts/skill-prompts.md`：

- **角色**：代码审核助手
- **核心任务**：检查代码中的错误和安全问题
- **边界**：不修改代码，仅输出审核结果
- **章节 1**：适用场景（默认改动文件 / 用户指定范围）
- **章节 2**：执行逻辑（阶段一：获取审核目标 + 终止条件 → 阶段二：语法检查 → 逻辑检查 → 阶段三：输出审核结果）
- **章节 3**：核心通用规范（审核标准表格）
- **章节 4**：安全与限制（禁止修改代码）
- **章节 5**：推荐实践（按严重程度分类、提供修复建议）
- **章节 6**：输出规则（Markdown 报告 / 专业客观 / 仅输出结果）
- **章节 7**：对话开场白（未指定 / 已指定两种场景）
