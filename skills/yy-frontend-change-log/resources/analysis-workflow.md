# 逻辑梳理工作流

## 分析策略指引

### 深度控制

分析深度取决于文件规模和用户需求，避免过度分析或遗漏关键信息：

- **小型文件（<100 行）**：完整分析所有导出、导入、逻辑和依赖。
- **中型文件（100-500 行）**：重点分析核心职责、关键状态/Props、主要交互事件和外部依赖。
- **大型文件（>500 行）**：仅分析核心职责和数据流概览，详细逻辑按函数/模块拆分后逐一说明。

当用户需求侧重变更记录时，业务说明精简到 1-2 句概述；当用户需求侧重逻辑梳理时，按完整分析项展开。

### 高效搜索引用关系

查找文件被引用关系时，使用以下策略避免遗漏：

- **组件文件**：用文件名（不含扩展名）在项目中搜索 `import` 语句，同时搜索动态导入 `() => import(` 和 `defineAsyncComponent`。
- **工具函数/模块**：搜索函数名或 `export` 的具名导出，关注解构导入 `import { xxx }`。
- **Store 模块**：搜索 store ID（Pinia）或模块名（Vuex），同时搜索 `useXxxStore` 调用。
- **样式文件**：搜索 `@import` 引用和 CSS Modules 的 `import styles from`。

搜索时优先使用文件名关键词而非完整路径，以捕获别名导入和相对路径变体。

### 常见遗漏点

分析过程中容易遗漏以下内容，需特别关注：

- **隐式依赖**：通过 `inject`/`useContext` 接收的数据、全局事件总线、`$attrs`/`$listeners` 透传。
- **副作用**：文件顶层的 IIFE、全局变量赋值、`addEventListener` 未清理、定时器未销毁。
- **条件导出**：`export default` 在不同环境下的条件分支（如 `if (process.env.NODE_ENV)`）。
- **动态组件**：`<component :is>` 或 `React.createElement` 动态创建的组件。
- **异步边界**：`Suspense`/`defineAsyncComponent`/`React.lazy` 包裹的异步加载逻辑。

### 工具使用建议

- 对于大型项目，使用 grep 搜索组件引用时，可先限定搜索目录范围（如 `src/`）排除 `node_modules`。
- 使用 ast-grep 搜索 AST 结构（如 `import { $$$ } from '$SOURCE'`）比正则更精确。
- 读取文件时，优先读取 `<script>` 部分和 `export default` 附近的代码，`<template>` 和 `<style>` 部分按需读取。

## 梳理顺序

对组件文件按以下顺序执行逻辑梳理，非组件文件仅执行基础分析项：

1. **收集组件信息**：读取组件代码，自动识别框架类型（Vue2/Vue3/React），根据框架选择对应专属分析流程。
2. **识别核心属性**：提取 Props 接口定义，识别 State/Ref/Context，明确每个属性的用途和约束。
3. **梳理生命周期/渲染逻辑**：分析渲染时机和触发条件，识别关键的 Hook 或生命周期方法，明确副作用和依赖关系。
4. **分析交互事件**：提取所有事件处理函数，明确触发条件和处理流程，追踪事件对状态的影响。
5. **整理依赖关系**：梳理子组件依赖，识别外部接口和服务依赖，明确数据传递路径。
6. **分析状态流转**：如涉及状态机或复杂状态变化，使用 Mermaid 状态图描述状态定义和流转规则。
7. **生成结构化文档**：按输出结构组织内容，使用 Mermaid 语法绘制流程图和状态图，确保文档清晰可读。

## 基础分析项

对所有目标文件执行：

- **业务职责**：文件 / 组件的核心功能是什么，解决什么业务问题（1-2 句），在整体架构中的定位（页面级组件 / 通用组件 / 工具模块 / 状态模块）。
- **数据流**：数据来源（Props / API / Store / 本地状态），数据流向，关键状态变量及更新触发条件。
- **交互关系**：依赖的组件 / 模块，使用的第三方库或工具函数，暴露的接口。
- **被引用关系**：搜索项目中引用本文件的所有文件，列出引用方。
  - 组件文件：搜索 `import` 引用和动态加载。
  - 工具函数 / API 模块：搜索调用方。
  - Store 模块：搜索消费方。
  - 无法确定类型：标记为"通用工具"或"基础设施"。
  - 找不到引用时：组件标记为"顶层页面"或"未被引用"；非组件标记为"未被引用"。

## 扩展逻辑梳理项（组件文件适用）

- **核心属性**：
  - **Props 接口**：属性名称、类型、是否必填、说明、默认值
  - **State 状态**：状态名称、类型、初始值、说明
  - **Ref / Context**：名称、用途、作用域
- **生命周期 / 渲染逻辑**：
  - 关键生命周期钩子或Hook的用途、执行时机、依赖项
  - 渲染触发条件和渲染内容分支
- **交互事件与处理流程**：
  - 所有交互事件的触发条件、处理函数、执行步骤和后置影响
- **依赖关系**：
  - 组件依赖的子组件、第三方库、API接口
  - 使用的状态管理方案（Vuex/Pinia/Redux/Context等）
- **框架专属特性**：
  - **Vue2**：详见 `resources/vue2-rules.md`
  - **Vue3**：详见 `resources/vue3-rules.md`
  - **React**：详见 `resources/react-rules.md`
- **状态流转**：
  - 组件内部的状态变化（如涉及状态机）
  - 所有可能的状态、触发事件和流转规则
  - 状态流转的前提条件
- **异常边界与处理**：
  - 异常场景和触发条件
  - 处理策略和回退方案
  - 框架专属异常处理机制（errorCaptured / Error Boundary 等）

识别为具体框架类型后，除执行通用分析项外，还需按对应框架专属规则执行分析。

## 通用规则（所有文件类型）

适用于 JS/TS 纯脚本、样式文件、文档/测试文件等非框架文件，以及框架文件的公共分析项：

- **导出分析**：识别所有 `export` 的函数、类、常量、类型，说明每个导出的用途和调用场景。
- **导入分析**：识别所有 `import`，区分第三方依赖、项目内部模块、相对路径引用，标注关键依赖的用途。
- **副作用识别**：文件顶层执行的副作用操作（IIFE、全局事件监听、全局变量赋值、polyfill 注入）。
- **类型定义**（TS 文件）：`interface` / `type` 定义的用途，与运行时逻辑的关系。
- **常量与配置**：文件级常量、配置对象的用途和影响范围。
- **样式文件额外规则**：CSS 类名层级关系、变量/混入定义、主题变量引用、媒体查询断点。
- **文档/测试文件额外规则**：测试文件分析覆盖的函数/组件、mock 策略、断言逻辑；文档文件分析对应的源文件和描述的业务模块。
