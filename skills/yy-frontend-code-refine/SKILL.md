# yy-frontend-code-refine

针对 Vue2/Vue3/React 组件与 JS/TS/JSX/TSX 文件的代码精炼技能。通过清理无效代码、整理导入排序、统一代码结构、规范命名、增强 Props，提升代码可读性与团队协作效率，降低维护与交接成本。

**核心边界**：不生成新组件、不改业务逻辑、不生成提交信息。任何涉及业务行为变更的操作必须先停下来与用户确认。

---

## 适用范围

| 维度     | 内容                                                                                        |
| -------- | ------------------------------------------------------------------------------------------- |
| 支持文件 | `.vue`（Options API / `<script setup>`）、`.js`、`.jsx`、`.ts`、`.tsx`                      |
| 默认目标 | `git diff --name-only HEAD` 与 `git diff --cached --name-only` 合并去重后过滤支持的文件类型 |
| 指定目标 | 用户指定的文件、目录（递归收集），或直接粘贴的代码内容                                      |
| 不支持   | 样式文件（`.css`、`.scss`、`.less`）；纯静态资源；新组件生成；业务逻辑变更                  |

无匹配文件时回复：_"当前没有需要精炼的改动文件。你可以指定文件或文件夹让我精炼。"_

## 任务清单与调度

### 任务总览

| ID  | 子技能         | 风险  | 执行者 | 适用文件                                 |
| --- | -------------- | ----- | ------ | ---------------------------------------- |
| T01 | 清理与导入整理 | 🟡 中 | 子代理 | `.vue` / `.js` / `.ts` / `.jsx` / `.tsx` |
| T02 | 代码结构排序   | 🟡 中 | 子代理 | `.vue` / `.js` / `.ts` / `.jsx` / `.tsx` |
| T03 | 语义化命名规范 | 🔴 高 | 主代理 | `.vue` / `.js` / `.ts` / `.jsx` / `.tsx` |
| T04 | Props 增强     | 🔴 高 | 主代理 | `.vue` / `.jsx` / `.tsx`                 |

**执行顺序**：T01 → T02 → T03 →（如适用）T04。

### 文件类型与任务匹配

| 文件类型        | 匹配任务           |
| --------------- | ------------------ |
| `.vue`          | T01, T02, T03, T04 |
| `.js` / `.ts`   | T01, T02, T03      |
| `.jsx` / `.tsx` | T01, T02, T03, T04 |

### 风险分级与执行规则

- **🟡 中风险**（T01/T02）：用户一次性确认后批量执行；可由子代理并行处理多个文件。
- **🔴 高风险**（T03/T04）：每项改动展示变更预览，逐项确认；只能由主代理串行执行。原因：命名与 Props 改动可能跨文件传播，子代理看不到完整影响范围。

### 调度流程

1. 扫描目标文件 → 生成任务清单 → 展示并**等待用户确认**。
2. 用户确认后：
   - 中风险任务：**按文件**分配子代理并行执行，每个子代理在自己负责的文件内**串行完成 T01 再做 T02**。
   - 高风险任务：由主代理串行执行，每项单独确认。
3. 完成后输出结果汇总。

> 注意"先 T01 后 T02"是**单文件内的顺序约束**，不是全局阶段：不要先把所有文件 T01 跑完再回头跑 T02，那样会起两轮子代理、浪费一倍 token 与上下文。每个子代理对自己那一份文件一次跑完 T01→T02 即可。

### 子代理调度细节

- **分配策略**：一个文件一个子代理，子代理只持有该文件上下文，避免文件间互相干扰。
- **单文件内顺序**：同一子代理负责的文件内，必须按 T01 → T02 串行执行；不要并行两个子任务到同一文件。
- **并行度上限**：同时运行子代理数 ≤ 5；超出则排队，前一批完成后再启动下一批。
- **失败隔离**：单个文件子代理失败时，该文件回滚（见"文件安全机制"），其他文件不受影响；汇总时单独标注失败文件与原因。
- **不传递改名结果**：T01/T02 完成后不要让子代理顺手做 T03/T04——高风险任务必须回到主代理。

### 无人类在场时的降级

当此技能在批处理或上游 agent 链路中被调用、检测不到人类确认通道时：

- 中风险任务仍可执行（已批量授权）。
- 高风险任务（T03/T04）**自动跳过**，在汇总里明确标注"因无确认通道而跳过 N 项"，并把建议清单一并输出，供后续人工 review。
- 不要自我授权执行高风险任务。

## 文件安全机制（强制）

修改任何文件按「备份 → 修改 → 删除备份」三步执行：

1. **备份**：将原文件复制为 `{原文件名}.{时间}.bak`（时间格式 `YYYYMMDDHHmmssSSS`，毫秒级，存放于同目录）。**若目标 `.bak` 已存在**（极少数同毫秒碰撞或并发情况），追加 4 位随机字母数字后缀；仍冲突则中止该文件处理并在汇总里报告"备份名碰撞，未执行"。
2. **修改**：按任务要求修改，完成后验证语法正确（能跑 `prettier --check` 或框架编译就跑一下）。
3. **删除备份**：确认修改无误后删除 `.bak`。

**异常处理**：

- 修改失败：从 `.bak` 恢复原文件，删除备份，在汇总中告知失败原因。
- 中断恢复：每次执行前先扫描目标目录，清理残留的 `.bak`（避免历史失败遗留干扰）；但**不要跨用户、跨任务批量清理**，只清理本次目标范围内的残留。

## 子技能简述与详细规则入口

四个子技能的可执行细节按主题拆分到 `references/`，按需读取：

| 任务 | 一句话说明                                                                | 详细规则                                                |
| ---- | ------------------------------------------------------------------------- | ------------------------------------------------------- |
| T01  | 删除未用 import/变量/函数；按 4 组排序导入                                | `references/tasks.md` §T01                              |
| T02  | Vue2 Options / Vue3 setup / React 各自的代码块顺序，含模板属性顺序        | `references/tasks.md` §T02 + `references/frameworks.md` |
| T03  | API/事件/常量/Props/Hooks/布尔值的命名规则；跨文件影响逐项确认            | `references/tasks.md` §T03 + `references/naming.md`     |
| T04  | Props 增强：明确 `type`/`default`，camelCase，加注释，复杂类型用 PropType | `references/tasks.md` §T04                              |

**代码风格、禁止规则、推荐与不推荐项**：见 `references/style.md`。这是精炼过程中的通用约束清单，模型遇到不确定的写法时回查。

> 关键提醒：T01 的"删除未用代码"必须遵守保留清单——`export` 函数、全局注册组件、字符串动态调用的方法一律不删。详见 `references/tasks.md` §T01。

````markdown

**执行任务**: T0X, T0Y, ...

- ⏭️ <跳过项描述>

#### T02 代码结构排序

- ✅ <变更项描述>

**变更对比（关键变更）**:

- 旧代码
+ 新代码

````

## 边界条件

| 场景       | 处理                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 部分精炼   | 用户指定仅执行某子技能时，仅执行指定项，跳过其他                     |
| 已符合规范 | 扫描后无需精炼的文件标注"无需精炼"                                   |
| 大型文件   | 超过 1000 行建议分批精炼                                             |
| 回滚保障   | 建议用户先提交当前状态，便于回滚                                     |
| 无人类在场 | 高风险任务自动跳过，输出建议清单（详见调度章节"无人类在场时的降级"） |
