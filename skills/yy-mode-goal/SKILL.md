# yy-mode-goal

## 描述

条件驱动的自主执行技能，基于"判题分离"机制：主模型执行任务，每轮校验是否满足验收条件，达标自动停止，不满足则继续下一轮。

## 使用场景

- 用户提到"修复所有错误"、"直到测试通过"、"持续优化直到达标"
- 用户需要批量修复代码报错、完善单元测试
- 用户要求完整开发某个功能模块、重构目录代码
- 用户需要清理项目所有 lint / 编译 / 接口异常
- 用户要求文档补全、批量改写直到符合规范

不应触发：

- 用户只是询问某个功能的实现方式
- 用户要求简单的目标设定或进度追踪（无执行需求）
- 用户明确要求手动控制每一步

## 指令

### 步骤 1. 设定目标和验收条件

理解用户目标，明确可量化的验收条件。

**目标设定规则**：

- **目标**：清晰描述要完成的任务（如"修复 src 下所有接口报错"）
- **验收条件**：可量化的完成标准（如"npm run test 全部通过"、"0 个 lint 错误"）
- **约束条件**：明确禁止修改的范围（如"不修改配置文件"）

**验收条件示例**：

```text
目标：修复 src 下所有接口报错
验收条件：
- npm run test 全部通过
- 无 TypeScript 类型错误
- 不修改 package.json 和 tsconfig.json
```

### 步骤 2. 分析任务并制定执行计划

分析当前状态，制定首轮执行计划。

**分析内容**：

- 当前错误/问题清单
- 优先级排序（按依赖关系、影响范围）
- 预计执行步骤

**执行计划模板**：

```text
首轮执行计划：
1. [任务 1] - [预期结果]
2. [任务 2] - [预期结果]
...
```

### 步骤 3. 执行任务

按计划执行任务，调用相应工具。

**执行规则**：

- 按计划顺序执行，记录每步结果
- 遇到阻塞时跳过并记录，继续其他任务
- 每步执行后记录实际结果

**执行记录模板**：

```text
执行记录：
- [任务 1]：[结果] ✅/❌
- [任务 2]：[结果] ✅/❌
...
```

### 步骤 4. 校验是否满足验收条件

执行完成后，校验是否满足步骤 1 设定的验收条件。

**校验方法**：

- 运行验收条件中指定的命令（如 `npm run test`）
- 检查输出是否符合预期
- 记录校验结果

**校验结果模板**：

```text
校验结果：
- [验收条件 1]：✅/❌ [实际结果]
- [验收条件 2]：✅/❌ [实际结果]
...
总体：通过/未通过
```

### 步骤 5. 判断是否继续

根据校验结果判断是否继续执行。

**决策分支**：

- **全部通过**：进入步骤 6 输出最终结果
- **部分通过**：分析未通过原因，制定下一轮计划，回到步骤 3
- **全部未通过**：重新分析问题，调整策略，回到步骤 2

**下一轮计划模板**：

```text
下一轮执行计划：
- 基于上一轮结果调整：[调整说明]
- 重点解决：[未通过的验收条件]
- 具体任务：[任务列表]
```

### 步骤 6. 输出最终结果

所有验收条件满足后，输出最终结果。

**输出内容**：

```text
目标达成报告
============
目标：[目标描述]
状态：✅ 已完成
执行轮次：[轮次数]

执行摘要：
- 第 1 轮：[主要成果]
- 第 2 轮：[主要成果]
...

最终状态：
- [验收条件 1]：✅ 通过
- [验收条件 2]：✅ 通过
...

关键成果：
- [成果 1]
- [成果 2]
...
```

## 安全边界

- 不修改验收条件中明确禁止的范围
- 每轮执行后必须校验验收条件，不得跳过
- 遇到无法解决的问题时，明确告知用户并等待指示
