# yy-generate-speech

## 描述

为不同项目或独立文本制作中文 MP3，默认采用 Serena 普通话女声、本地 CPU 推理。生成器和参数随技能分发，模型、Python 环境、音频和项目数据不随技能发布。当前脚本仅封装中文短句配音，不承诺长文、其他语言或逐音节节奏控制。

## 使用场景

- 将中文文字、文本文件或批量语料制作为语音文件。
- 根据试听反馈调整声调、拖音、节奏或多余音节。

不应触发：

- 语音识别、录音转写、声音克隆或音乐制作。
- 制作需要专业来源与核验的标准音素材。

## 指令

### 步骤 1. 确定文本与目标项目

- 明确目标项目根目录及正式交付位置；独立文本使用用户指定的工作目录。未指定且当前目录属于目标项目时使用当前目录，有歧义时询问。
- 保留原文，用实际生成输入明确数字、缩写、多音字的读法，不为修声调擅自使用同音替字。
- 长文按句拆分，记录顺序和停顿，先制作代表性片段再批量生成。
- 临时候选、输入文件和试听记录统一放在目标项目根目录 .temp/ 下，可随时删除；正式资源和模型不得存入该目录。
- 所有项目走同一生成流程。项目有清单、资源接入或版本约定时，按该项目要求采纳；生成器不自动查找业务目录或修改业务清单。未提供项目适配规则时只交付候选音频及元数据。

### 步骤 2. 核对本地环境

- 从当前 SKILL.md 所在目录定位 scripts，使用脚本绝对路径；技能可以安装在任意目录。
- 首次准备或环境缺失时读取 [Qwen 本地环境说明](resources/qwen-local.md)，只在用户授权后安装依赖或下载模型。已就绪时直接复用，不重复安装。
- 由脚本解析配置，优先级为 --config、触发时当前工作目录所属 Git 根目录 .env、进程环境变量、本机历史配置、有限本地探测；--project-root 不改变配置查找位置。只读取技能变量，不执行 .env 内容。
- 使用 --check-env 集中检查环境，不安装、不下载、不加载模型或保存配置。缺少配置时先检查报告；需要手动指定时，设置 QWEN_TTS_HOME，或同时设置 QWEN_TTS_PYTHON 与 QWEN_TTS_MODEL_DIR。FFmpeg、ffprobe 可分别使用 QWEN_TTS_FFMPEG、QWEN_TTS_FFPROBE 指定。
- 普通生成在环境验证通过后，向已有根目录 .env 补入缺失或空白的技能配置，并保存本机历史配置。没有 .env 时不新建；已有非空配置失效时报告，不静默覆盖。配置与保存位置见环境说明。
- 确认 Node.js 22.18+、Python 3.12、本地 Qwen3-TTS 环境、固定版本模型、FFmpeg 和 ffprobe 可用。生成期间保持离线；缺少依赖时报告具体问题，不切换在线服务或系统 TTS。
- 默认配方见 [recipe.mts](scripts/recipe.mts)。项目传入配方时优先采用项目要求，但仍须与本地模型来源记录一致；不因本次候选调整修改公共默认配方或其他已确认条目。

### 步骤 3. 生成独立候选

显式传入目标项目根目录，避免从技能安装位置推算项目。下列占位符均替换为实际绝对路径；先预览再执行。

```powershell
node "<技能目录>/scripts/generate-speech.mts" --project-root="<目标项目>" --text="你好，欢迎使用。" --dry-run
node "<技能目录>/scripts/generate-speech.mts" --project-root="<目标项目>" --text="你好，欢迎使用。"
```

- --project-root：目标项目根目录，省略时为当前工作目录；相对输入、输出路径均以它为基准。
- --text 与 --file：二选一。UTF-8 .txt 文件作为一个完整文本输入；.json 文件须为非空字符串数组，按数组顺序生成。
- --output-dir：可选，指定输出目录；省略时使用目标项目 .temp/tts/candidates/<唯一标识>/。
- --seed：可选，非负安全整数，覆盖本次候选随机种子。
- --sampling：可选，只能为 true 或 false，覆盖是否启用随机采样。
- --dry-run：只打印文本、有效配方和输出路径，不加载模型、不生成文件。
- --help：显示简要用法。
- --config：显式 JSON 配置文件，使用环境说明中的同名变量键，优先于自动读取的 .env。
- --check-env：无需提供文本，只检查环境并报告状态、版本与配置来源，不写入配置。

批量输入格式：

```json
["第一句。", "第二句。"]
```

```powershell
node "<技能目录>/scripts/generate-speech.mts" --project-root="<目标项目>" --file=".temp/texts.json" --seed=24 --sampling=false
```

生成器将临时请求及转码文件放入目标项目 .temp/tts/ 并在结束后清理。每个 MP3 旁保存 .metadata.json，记录实际输入、模型配方、运行时版本、SHA-256 和时长。文件名包含文本与配方摘要；已有音频或元数据不覆盖，调整及重试使用新的候选目录。

程序接入时可导入 scripts/qwen.mts 的 runQwen(recipe, tasks, { projectRoot })。每项任务包含 id、text、output，可选 qwen.seed、qwen.sampling、baseSha256；该接口允许调用方重制已有输出，调用方负责保护正式版本及维护版本关系。

### 步骤 4. 核验并调整

生成完成自动检查 MP3 解码、时长、音量、削波及静音占比；失败时报告失败，不把产物记为通过。独立检查已有音频：

```powershell
node "<技能目录>/scripts/generate-speech.mts" --project-root="<目标项目>" --inspect="<音频路径>.mp3"
```

- 用音频绝对路径提供 Markdown 试听入口，少量列出候选及参数差异；机器通过仍为待试听。
- 报 token 上限或疑似截断时拆短文本。当前质量门槛仅接受 0.15 至 30 秒的 MP3，不适合直接输入整篇长文。
- 拖音先区分静音与元音持续；仅静音调整首尾处理，元音、声调和节奏问题先核对原字及标点，再比较 seed 或 sampling=false。
- 保留整句上下文判断自然度，不整体有损变速、不裁切元音，不承诺逐音节精确时长。
- 每次只改必要参数，记录差异，不因单条反馈批量重制其他已确认内容。

### 步骤 5. 采纳与记录

生成后即可交付候选；只有用户试听认可后才标为通过或替换正式版本，已有明确认可不重复确认。将音频、元数据和记录一起交付至用户指定位置。不同项目按其既有资源方式接入，文件换版须待复听并保留旧结论。

在任务目录维护 review.md，使用以下格式：

```markdown
# 配音记录

- 模型与版本：<模型标识及 revision>
- 有效配方：<元数据文件链接>

| ID   | 原文   | 朗读文本   | 文件       | SHA-256 | 参数差异 | 状态                        | 用户反馈 | 更新时间 |
| ---- | ------ | ---------- | ---------- | ------- | -------- | --------------------------- | -------- | -------- |
| <ID> | <原文> | <实际输入> | <相对路径> | <摘要>  | <seed等> | <待试听/通过/需调整/待复听> | <原话>   | <时间>   |
```

### 步骤 6. 输出结果

先说明失败或未验收项，再给音频试听及文件位置，最后说明机器检查结果和待试听状态。附元数据与记录链接，说明参数差异；未生成文件时报告实际阻塞原因。

## 安全边界

- 不调用在线合成服务，不将系统 TTS 产物冒充模型生成音频。
- 不自动发布、上传、提交代码或覆盖已认可的正式音频。
- 仅自动读写 .env 中的技能路径变量及用户级历史配置，不处理凭据或其他变量；不在公开技能文件中记录账号、私人语料、本机绝对路径或项目专属信息。
- 程序检查不能代替发音、听感、许可或专业标准的人工核验。
