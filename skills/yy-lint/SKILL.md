# yy-lint

## 描述

执行代码 lint 检查，自动检测 lint 脚本、验证 Node 版本、执行检查并尝试自动修复报错（不修复警告）。支持自定义命令。

## 使用场景

- 用户提到"lint"、"代码检查"、"代码风格检查"
- 用户要求运行 lint 检查
- 用户要求检查代码风格问题
- 用户指定自定义 lint 命令（如 `/yy-lint npm run eslint:fix`）

不应触发：

- 用户只是查看代码
- 用户要求重构代码
- 用户要求修复 bug（除非明确提到 lint）
- 用户要求编写测试

## 指令

### 步骤 1. 确定执行命令

按优先级确定要执行的命令：

1. 用户明确指定的命令（如 `/yy-lint npm run eslint:fix`）
2. `package.json` 中的 `lint:fix` 脚本
3. `package.json` 中的 `lint` 脚本

**决策分支**：

- **有可用命令**：进入步骤 2
- **无可用命令**：提示用户并结束执行

### 步骤 2. 验证 Node 版本

检查 `.nvmrc` 文件是否存在：

- **不存在**：跳过版本验证，继续执行
- **存在**：验证当前 Node 版本是否满足要求
  - **满足**：继续执行
  - **不满足**：显示警告并结束执行

### 步骤 3. 执行 lint 检查

执行确定的命令并捕获 exit code：

- **exit code 为 0**：检测通过，显示成功消息，**不读取输出日志**（节省 token）
- **exit code 非 0**：读取错误日志，仅修复报错，不修复警告

**错误修复边界**：

- 正面解决问题，不得绕过（如添加 `any` 类型、删除功能代码）
- 警告不自动修复，保留供人工评估

**并行任务约束**：

- 若有多个任务正在并行执行（同时修改文件），**不执行 lint**
- 等所有并行任务完成后，再统一执行

### 步骤 4. 输出结果

输出格式：执行状态、命令名称、报错数量（如有）、修复结果（如有）。

详细工作流程参考 `resources/workflow.md`，输出示例参考 `examples/output.md`。

## 安全边界

**禁止主动执行的命令**：

- 除 `npm run lint:fix` 或 `npm run lint` 外的其他 package.json 脚本
- 编译、构建、部署命令
- 自动执行的测试命令
- 除 `node --version` 外的其他 npx 命令
