# 通用注释规则

适用于所有编程语言。当特定语言的规则与本文件冲突时，以特定语言的规则优先。

## 判断标准

- 业务规则/领域逻辑：✅ 必须注释（涉及特定业务知识，非开发者难以理解）
- 复杂算法：✅ 必须注释（阅读时间 > 30 秒的逻辑）
- 非直观的边界处理：✅ 必须注释（如特殊的数据转换、兼容性处理）
- 重要的分支判断：✅ 必须注释
- 递归调用：✅ 必须注释
- 特殊处理的边界情况：✅ 必须注释
- 纯技术实现：⚠️ 视情况（通用技术模式如循环、映射不需要）
- 自解释代码：❌ 不需要（变量名、函数名已清晰表达意图）

## 注释质量原则

- 注释解释"为什么"，而非"做什么"（代码本身应说明"做什么"）
- 一行能说清就一行
- 仅对重要逻辑添加注释，避免过度注释
- 已有注释内容正确则保留，仅在缺失处补充；内容过时则修正
- 文档注释描述功能、参数、返回值和异常；内部注释解释设计意图和决策原因

## 避免的注释

```python
# ❌ 显而易见的注释
i = i + 1  # i 加 1

# ❌ 重复代码含义
# 遍历数组
for item in items:
    pass

# ❌ 重复类型信息（类型系统已表达）
# ❌ 对每行代码都加注释
```

## 注释标注约定

格式规范：

```text
TODO(责任人): 待办说明 [可选期限]
FIXME(责任人): 问题说明
HACK: 临时方案说明，待 xxx 条件满足后移除
```

使用场景：

- **TODO**：已知需要补充或优化的点，当前不阻塞功能
- **FIXME**：已知的缺陷或隐患，需要尽快修复
- **HACK**：临时绕过方案，必须说明移除条件

## 注释语言

- 默认使用中文
- 以下情况使用其他语言：
  - 用户明确指定注释语言
  - 项目 AGENTS.md 中另行指定
  - 代码标识符、技术术语保留原文
