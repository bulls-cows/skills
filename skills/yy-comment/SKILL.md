# yy-comment

## 使用场景

当用户表达以下意图时触发：

- 为代码文件或指定函数添加注释
- 补充 JSDoc 文档注释
- 为 HTML/Vue 模板添加结构注释
- 为 CSS/SCSS/LESS 添加样式注释

不应触发：

- 用户要求实现新功能、修改代码逻辑或删除代码
- 文件已有完整注释且用户未明确要求补充
- 用户要求为每个标签/每条规则都加注释（过度注释）

## 基础原则

- 已有注释内容正确则保留，仅在缺失处补充；内容过时则修正
- 注释使用中文
- JSDoc 描述函数"做什么"，内部注释解释"为什么"这样做
- 仅对重要逻辑添加注释，避免过度注释
- 保持注释简洁，一行能说清就一行

## 文件类型与注释语法

| 文件类型                                | 注释语法                     |
| --------------------------------------- | ---------------------------- |
| `.js`/`.ts`/`.jsx`/`.tsx`/`.mjs`/`.cjs` | JSDoc `/** */` 和行注释 `//` |
| `.html`、Vue `<template>`               | `<!-- 注释 -->`              |
| `.jsx`/`.tsx`（JSX 部分）               | `{/* 注释 */}`               |
| `.css`                                  | `/* 注释 */`                 |
| `.scss`/`.less`                         | `/* 注释 */` 或 `//`         |

Vue SFC 中三个区块各自使用对应语法，互不干扰。

## 执行流程

### 1. 确定范围

- 用户指定文件 → 读取目标文件
- 用户指定函数 → 定位目标函数
- 用户未指定 → 询问为整个文件还是特定函数添加注释

识别文件中的内容类型：

- **脚本代码**：`.js`/`.ts`/`.jsx`/`.tsx`/`.mjs`/`.cjs` 文件，或 Vue SFC 的 `<script>` 部分
- **模板内容**：`.html` 文件、Vue SFC 的 `<template>` 部分、JSX/TSX 的 return 中的 JSX
- **样式内容**：`.css`/`.scss`/`.less` 文件，或 Vue SFC 的 `<style>` 部分

对于超过 500 行的文件，先告知用户文件规模，确认后再执行。

### 2. 添加脚本注释

按 `references/script.md` 的规范执行：

- 为函数/类/方法添加 JSDoc 文档注释（`@param`、`@returns`、`@throws` 等）
- 为 TypeScript interface/type/enum 添加文档注释
- 为重要模块级常量添加注释
- 在关键逻辑步骤前添加内部注释（解释"为什么"）
- 跳过自解释代码和显而易见的逻辑

### 3. 添加模板注释

按 `references/template-style.md` 的规范执行：

- 识别语义化区块（header/nav/main/footer/aside/section）和功能性 div 区域
- 识别复杂交互组件（表单组、模态框、下拉菜单、标签页、抽屉等）
- 在关键节点上方添加注释，说明业务用途
- 不为每个标签添加注释，不为自解释的语义标签添加注释

### 4. 添加样式注释

按 `references/template-style.md` 的规范执行：

- 使用 `/* ========== 区块名称 ========== */` 格式分隔样式区块
- 对魔术数字、Hack、兼容性处理添加行内说明注释
- 对复杂选择器添加说明
- 不为每条规则添加注释，不为自解释属性添加注释

### 5. 输出结果

修改目标文件后，报告：

- 添加了注释的函数/类/接口列表
- 各类注释数量：文档注释 N 处、内部逻辑注释 N 处、模板注释 N 处、样式注释 N 处
