# yy-extract-traits

从 Git 提交记录中分析并提炼开发者的核心特质。

## 描述

通过分析开发者的 Git 提交历史，从人的性格特质角度提炼核心特征，而非停留在操作层面。

## 使用场景

- 用户想要分析自己的开发风格
- 用户想要提炼个人特质
- 用户想要生成开发者画像

不应触发：

- 用户只是查看提交历史
- 用户要求统计代码量或提交数量
- 用户要求分析其他开发者的代码

## 指令

### 1. 确定分析范围

询问用户以下问题（可合并询问）：

1. 分析哪个时间范围的提交？（默认：最近一周）
2. 是否限定特定作者？（默认：当前 Git 用户）

### 2. 获取提交记录

执行以下命令获取提交记录：

```bash
git log --since="<开始日期>" --until="<结束日期>" --author="<作者名>" --pretty=format:"%h %s" --no-merges
```

### 3. 分析提交模式

从以下维度分析提交信息：

- **提交类型分布**：feat/fix/refactor/docs/chore 等的比例
- **高频关键词**：识别反复出现的动词和名词
- **改动意图**：理解每次改动背后的动机
- **行为一致性**：观察是否有持续的行为模式

### 4. 提炼特质

从人的性格特质角度提炼，而非操作层面：

- **不要**：使用"DRY 原则践行者""结构化思维"等操作描述
- **应该**：使用"追求本质""系统化思考""长期主义"等性格特质

提炼原则：

1. 每条特质用一句话概括，包含特质名称和具体表现
2. 特质数量控制在 3-5 条
3. 基于提交证据，不做主观臆断
4. 从"为什么这么做"的角度理解，而非"做了什么"

### 5. 输出结果

以列表形式输出提炼结果：

```markdown
- **特质1**：具体表现说明
- **特质2**：具体表现说明
- **特质3**：具体表现说明
```

## 示例

### 输入

```text
分析我最近一周的提交记录，提炼我的核心特质
```

### 输出

```markdown
- **追求本质**：不喜欢形式主义，关注事物的核心价值，倾向删繁就简
- **系统化思考**：有构建体系的习惯，修改不是零散的，而是为了整体一致性
- **长期主义**：愿意为未来投入，建立规范、重构结构，不只是解决当下问题
- **知识复用**：有记录经验的习惯，希望后续 AI 也能遵循同样思路
```
