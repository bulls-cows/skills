# 源码取证

## 证据层次

- 源码、实际启用的配置：支持“当前实现”。区分功能存在与当前配置可进入该分支。
- 测试：支持被覆盖场景的预期行为；未运行测试不得写“验证通过”。
- 项目文档：支持设计意图；与代码不符时分别陈述，不静默合并。
- 行业标准、权威资料：支持业务背景，不证明本项目已按标准实现。
- 编译产物、缺失外部项目、推断：只作辅助分析，显式标注局限。

## 定位方法

优先精确搜索配置键、入口、符号及调用者，再读完整函数上下文；不要仅凭文件名推断职责。以一条用户操作、请求、命令或事件为单位追踪输入到输出，补足必要共享层和失败路径。

路径使用项目相对路径。行号从当前文件取得，记录日期；可取得版本标识时记录，无法取得时记录“工作区快照，未取得版本标识”。代码片段被截断或排版换行后，仍注明原文件范围和处理方式。

```text
源码：app/src/main/java/example/Reader.kt
符号：Reader.open；原文件第 40–65 行
处理：节选，省略日志，长参数按阅读需要换行
结论：由当前源码确认 / 由配置确认 / 推断 / 未验证
```

## 科普与业务边界

围绕读者当前理解障碍补概念：是什么、为什么需要、如何映射到项目中的输入输出。不要将一个项目约定泛化成行业通用事实。涉及安全操作、医法财知识、设备控制或陌生协议细节时核实权威来源，区分知识解释与操作建议；没有实机验证不声称设备行为已确认。

保留来源名称、文档版本/日期及可回查地址；本地项目文档记录路径。源码职责说明不替代专业资质或安全操作规程。
