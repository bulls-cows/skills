# yy-write-project-book

## 描述

把陌生代码库组织成可连续阅读的 Markdown 书稿：先建立项目全貌，再深入主要功能链路。交付章节、书籍配置和持久化进度，不构建电子书，不依赖其他技能才能完成写作。

## 使用场景

- 用户要求根据项目代码写一本项目导读、源码阅读手册或技术书籍。
- 用户需要分批撰写、补写或跨会话继续这类书稿。

不应触发：

- 用户只需要项目概览、单个函数解释或某条链路的学习文档，不需要书籍组织。
- 用户要求审核、修改业务源码，或将已有书稿转换为 EPUB/PDF。

## 指令

### 步骤 1. 确定书籍范围与续写状态

确定项目位置、读者背景、书名、章节范围、输出目录和篇幅。未指定时：中文、面向有编程经验但不熟悉项目及业务领域的读者，参考排版约 200 页，不要求精确；不为凑页数填充正文。默认输出目录为目标项目的 `docs/ebook/`，受项目写入范围限制时先确认位置。

- **首次写作**：提出书名和总目录，说明覆盖/排除范围及批次安排，等待确认；用户已确认则复用决策，不重新提问。
- **已有书稿**：先读 `progress.md`、`book-plan.md`、`book.json` 以及当前批次章节，按下一步续写，不从头重写。
- **关键选择缺失且会改变主题或覆盖范围**：只询问缺失选择；其余采用默认值并记录。

每轮默认完成一个章节或一个能独立验收的小节。用户授权自动继续时可连续完成多个小批次，但每批都必须先落盘进度，接近上下文容量时在批次边界停止。

### 步骤 2. 建立源码依据与阅读路线

先读适用项目规约，再核对根级配置、启动入口、主要模块和测试。按 [resources/source-evidence.md](resources/source-evidence.md) 建立证据；根据 [resources/stack-routing.md](resources/stack-routing.md) 选择技术栈入口。特定层定位规则优先于通用层规则，未列技术栈使用该文件的兜底路线；事实仍以当前源码为依据。

不要一次性读取整仓库。先形成项目地图，再围绕下一章追踪入口、输入、调度、处理、输出和失败分支。生成文件或外部源码不可达时标注边界，不把编译产物当作最新可维护源码。

### 步骤 3. 初始化书稿文件

使用 [templates/book-plan.md](templates/book-plan.md)、[templates/progress.md](templates/progress.md) 初始化已确认的规划和进度；占位字段必须替换为实际值，无证据时明确写“未取得”，不得编造。文件已存在时保留用户改动，仅更新本次相关部分。

规划采用总分结构：项目导读、主要源码链路、查阅附录。业务科普放在首次需要相关概念的章节中，附录只集中列术语，不让正文依赖读者预先读完附录。章节文件使用稳定名称，例如 `chapters/01-overview.md`；已有命名保留。

配置使用以下格式；章节按阅读顺序列出，新增章节文件实际落盘后再加入配置，尚未撰写的章节只留在规划中：

```json
{
  "title": "实际书名",
  "language": "zh-CN",
  "theme": "eink",
  "output": "output/project-book.epub",
  "chapters": [{"file": "chapters/01-overview.md", "title": "第一章：项目导读"}]
}
```

空书稿阶段不创建含虚假章节的配置。所有配置路径相对 book.json；作者只在用户提供时填入，封面仅在实际存在时配置。

### 步骤 4. 按小批次撰写与自检

按 [templates/chapter.md](templates/chapter.md) 组织正文，按 [resources/manuscript-contract.md](resources/manuscript-contract.md) 输出可构建 Markdown。模板是章节结构，不要求每章机械重复所有小节；无关小节可删除，但保留源码依据、边界及阅读顺序。

- 先讲这一章解决的问题，再补必要的业务概念，随后解释真实代码如何实现。
- 每条关键结论核对源码、配置或测试；精选最小片段并说明上下游，避免把大文件全文抄成书。
- 代码附近注明项目相对路径、符号和读取时行号。长代码换行或省略时标明摘录处理；不能把改写片段伪装成原始代码。
- 对业务科普区分通用概念、项目实际做法与未验证假设。高风险领域知识或不确定专业知识用权威资料核实，正文保留来源名称及可回查链接；没有依据则注明不确定。
- 每批自检：调用链可追踪、源码引用可定位、术语初次出现有解释、代码片段适合窄屏、无重复铺陈、无密钥或个人信息。

### 步骤 5. 记录进度与恢复点

每批完成后按顺序：落盘章节 → 更新 book.json → 更新 progress.md。未完成章节不标记为完成；部分正文可以保存，但必须标注草稿及准确的续写小节。

记录本批变更、关键决策、已核对的文件与符号、未验证项、下一步及其必读文件；不要只写“继续下一章”。记录源码读取日期和可取得的版本信息；不得为获取版本违背项目对命令的限制。

新会话恢复时重新核对本批将引用的源码。**源码改变**：先记录受影响结论并修订对应小节；**源码未改变**：沿用已核验结论。无需因版本变化无差别重写全书。

### 步骤 6. 验收与交付

收尾检查总目录与实际章节对应、配置只引用现有文件、章节链接有效、术语与证据一致，并将写作状态标为“书稿完成”而不是“电子书完成”。约 200 页仅为默认参考目标；没有实际排版产物时不得声称已测得页数。

每轮交付格式：

```text
本批完成：章节/小节及状态
文件：本批修改的书稿、配置、进度路径
核对：关键源码依据与未验证项
下一步：准确续写点；写完时说明可交给 EPUB 构建流程
```

## 安全边界

- 阅读项目不意味着授权修改源码、执行车辆/设备通信、发布、部署或提交。
- 只写已授权的书稿目录；已有用户修改不得静默覆盖。
- 不复制敏感配置、大段第三方受限内容或不可公开源码到交付书稿；发现敏感内容时用脱敏摘录或只说明职责。
- 本技能不生成 EPUB、HTML 或 PDF；用户同时要求电子书时，将完成的书稿交给独立构建流程并分别报告状态。
