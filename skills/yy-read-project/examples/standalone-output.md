# 输出示例：独立项目局部阅读

本文档展示 `yy-read-project` 在独立项目局部阅读场景下的预期输出结构。

## 示例 1：`src/auth` 模块局部阅读

```markdown
## 一句话定位

这是一个以 Web 管理后台为主的独立项目，`src/auth` 负责登录态建立、权限校验和会话相关流程，是前端访问业务页面前的入口层之一。

## 当前阅读范围

- **阅读模式**：局部阅读
- **目标对象**：`src/auth`
- **范围说明**：
  - **事实**：本次重点检查了 `src/auth/`、根级 `package.json`、`src/router/`、`src/api/` 与权限守卫相关入口文件。
  - **推断**：这些位置足以判断认证模块在整体中的职责、依赖方向和接入方式。
  - **未确认项**：未继续展开二级业务页面内部如何消费权限结果。
  - **依据位置**：`package.json`、`src/auth/`、`src/router/index.ts`

## 项目形态

- **项目类型**：独立项目
- **组织方式**：单应用
- **主语言栈**：TypeScript
- **根级关键文件**：`package.json`、`src/main.ts`、`src/router/index.ts`
- **整体结构判断**：
  - **事实**：项目以单前端应用结构组织，认证模块位于 `src/` 内部。
  - **推断**：`src/auth` 不是独立服务，而是应用内领域模块。
  - **未确认项**：是否还存在服务端同名配套模块，当前未看到。
  - **依据位置**：根目录结构、`src/` 分层

## 结构职责

### 独立项目

| 模块/目录    | 类型   | 主要职责                 | 关键依赖或调用方向                  |
| ------------ | ------ | ------------------------ | ----------------------------------- |
| `src/auth`   | module | 登录、会话、权限校验入口 | 被路由守卫调用，向 `src/api` 发请求 |
| `src/router` | module | 页面路由与守卫挂载       | 依赖 `src/auth` 的鉴权结果          |
| `src/api`    | module | 服务端接口封装           | 被 `src/auth` 调用                  |

- **结构补充判断**：
  - **事实**：认证逻辑集中在单模块内，对外主要暴露登录态检查和权限结果。
  - **推断**：这里是前端应用主链路上的横切能力模块。
  - **未确认项**：刷新 token 是否由单独模块负责。
  - **依据位置**：`src/auth/`、`src/router/`

## 全局关系

- **独立项目**：根入口启动应用后，路由层在导航前调用认证模块，认证模块再通过接口层读取或刷新会话状态。
- **monorepo**：不适用
- **关系判断**：
  - **事实**：`src/router` 依赖鉴权结果，`src/auth` 依赖接口层。
  - **推断**：认证模块位于“路由入口”和“业务页面”之间。
  - **未确认项**：是否存在状态管理层中转。
  - **依据位置**：路由守卫、认证入口、接口调用文件

## 技术栈边界

- **编程语言与运行时**：TypeScript + 浏览器运行时
- **职责分工**：前端应用、认证逻辑和接口封装均位于同一运行时内。
- **技术栈判断**：
  - **事实**：当前只发现前端 TypeScript 应用。
  - **推断**：认证相关能力未拆成独立进程或独立服务端子工程。
  - **未确认项**：是否存在构建期生成的权限类型文件。
  - **依据位置**：`package.json`、`src/` 目录

## 本地化方案

- **是否存在系统化 i18n**：待确认
- **入口与资源位置**：当前局部阅读未发现 `src/auth` 自身携带独立语言包
- **切换与加载方式**：待确认
- **文案归属边界**：认证模块更像消费文案，而非定义全局 i18n 规则
- **本地化判断**：
  - **事实**：本次没有在目标模块附近看到明确 i18n 入口。
  - **推断**：如果项目有统一 i18n，入口更可能在 `src/main.ts` 或应用壳层。
  - **未确认项**：全局语言切换与认证错误文案映射位置。
  - **依据位置**：`src/auth/`、`src/main.ts`

## 依赖与通信

### 共享契约或共享代码

- `src/auth` 复用 `src/api` 的请求封装和部分类型定义。

### 运行时通信

- 路由守卫调用 `src/auth` 的登录态检查逻辑。
- `src/auth` 通过 HTTP 请求访问后端会话接口。

- **通信判断**：
  - **事实**：同时存在源码级依赖和前后端 HTTP 通信。
  - **推断**：认证模块是前端接入后端会话能力的主要适配层。
  - **未确认项**：是否还存在 iframe 或消息总线式登录桥接。
  - **依据位置**：认证服务文件、路由守卫、请求封装

## 推荐阅读顺序

1. `package.json`
2. `src/router/index.ts`
3. `src/auth` 的入口文件
4. `src/api` 中会话相关接口定义

## 未确认项

- token 刷新链路是否完全在 `src/auth` 内闭环
- 权限结果是否会同步到全局状态管理
```
