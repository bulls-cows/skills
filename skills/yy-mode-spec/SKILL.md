# yy-mode-spec

## 描述

规格优先开发模式，要求在实施前完成详细规格文档编写，确保需求、设计、任务分解和验证标准全部明确后再开始编码。

## 使用场景

- 用户输入 `/yy-mode-spec` 命令
- 用户需要在编码前制定详细规格说明
- 用户要求先写规格文档再开发

不应触发：

- 用户直接要求执行某个任务，未提及规格文档
- 用户只是询问项目信息
- 用户要求制定简单计划（应使用 yy-mode-plan）

## 指令

### 1. 分析需求复杂度

读取用户需求，判断任务复杂度：

**简单需求**（直接在对话中输出规格）：

- 单文件修改或少量文件变更
- 功能单一、逻辑清晰
- 不涉及架构变更

**复杂需求**（创建规格文件）：

- 多模块、多文件变更
- 涉及架构设计或技术选型
- 需要多阶段实施

### 2. 编写规格内容

根据需求编写规格文档，包含以下要素：

- **功能概述**：核心价值和目标
- **需求分析**：功能性需求和非功能性需求
- **技术设计**：架构设计、API 规格、数据模型
- **核心代码示例**：关键函数签名、数据结构定义、核心逻辑片段，让使用者直观看到预期变更
- **任务分解**：有序的实施任务列表、依赖关系、验收标准
- **验证清单**：实施前、实施中、实施后的检查项

### 3. 确定输出方式

**简单需求**：直接在对话中展示规格内容。

**复杂需求**：创建规格文件，执行以下步骤：

1. 确定工具目录：按 `.agents` > `.claude` > `.opencode` > `.trae` 顺序检测，或使用用户指定的 `--tool-dir` 参数
2. 创建规格目录：`{工具目录}/specs/{时间戳}_{需求目录}/`
3. 生成三个文件：`spec.md`、`tasks.md`、`checklist.md`

时间戳格式：`YYYYMMDD_HHMMSS`，如 `20260324_153045_实时通知系统`。

### 4. 展示规格并等待确认

向用户展示规格内容，等待确认。

### 5. 处理用户反馈

- **用户确认**：开始执行实施
- **用户拒绝**：根据反馈调整规格，重新展示
- **用户要求调整**：修改对应部分，重新展示

### 6. 执行实施

用户确认后执行：

1. 创建待办事项列表
2. 按任务分解顺序执行
3. 完成后运行验证清单

### 7. 输出结果

输出格式如下：

```markdown
## 规格已创建

**规格目录**：[规格文件路径]

### 规格摘要

[功能概述和关键需求]

### 任务概览

[任务数量和阶段划分]

---

请确认是否执行此规格。
```
