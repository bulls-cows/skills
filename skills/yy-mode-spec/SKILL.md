# yy-mode-spec

## 描述

规格优先开发模式，要求在实施前完成详细规格文档编写，确保需求、设计、任务分解和验证标准全部明确后再开始编码。

## 使用场景

- 用户输入 `/yy-mode-spec` 命令
- 用户需要在编码前制定详细规格说明
- 用户要求先写规格文档再开发

不应触发：

- 用户直接要求执行某个任务，未提及规格文档
- 用户只是询问项目信息
- 用户要求制定简单计划（应使用 yy-mode-plan）

## 指令

### 1. 理解需求

分析用户需求，判断任务复杂度：

**简单需求**（直接在对话中输出规格）：

- 单文件修改或少量文件变更
- 功能单一、逻辑清晰
- 不涉及架构变更

**复杂需求**（创建规格文件）：

- 多模块、多文件变更
- 涉及架构设计或技术选型
- 需要多阶段实施

### 2. 编写规格

根据需求编写规格文档，包含以下要素：

- **功能概述**：核心价值和目标
- **需求分析**：功能性需求和非功能性需求
- **技术设计**：架构设计、API 规格、数据模型
- **任务分解**：有序的实施任务列表、依赖关系、验收标准
- **验证清单**：实施前、实施中、实施后的检查项

### 3. 创建规格文件

复杂需求需创建三个规格文件：

- `spec.md` - 主规格文档（参考 [templates/spec-template.md](./templates/spec-template.md)）
- `tasks.md` - 任务分解（参考 [templates/tasks-template.md](./templates/tasks-template.md)）
- `checklist.md` - 验证清单（参考 [templates/checklist-template.md](./templates/checklist-template.md)）

#### 目录选择优先级

1. **用户手动指定**（最高优先级）
   - 格式：`--tool-dir <目录> --requirement-dir <目录>`
2. **自动检测**：按 `.agents` > `.claude` > `.opencode` > `.trae` 顺序检测
3. **无匹配目录**：提示用户指定或创建

#### 目录结构

```text
{项目根目录}/
└── {工具目录}/
    └── specs/
        └── {时间戳}_{需求目录}/
            ├── spec.md
            ├── tasks.md
            └── checklist.md
```

时间戳格式：`YYYYMMDD_HHMMSS`，如 `20260324_153045_实时通知系统`。

### 4. 展示规格

向用户展示规格内容，等待确认。

### 5. 处理用户反馈

- **用户确认**：开始执行
- **用户拒绝**：根据反馈调整规格，重新展示

### 6. 执行实施

用户确认后：

1. 更新/创建待办事项列表
2. 按任务分解执行
3. 完成后运行验证清单

## 输出格式

- 必须展示规格内容
- 必须等待用户确认
- 复杂需求必须说明规格文件路径
