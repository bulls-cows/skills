# yy-mode-plan

## 描述

计划优先执行模式，要求在做出任何变更前必须获得用户确认，确保实施方向正确。

## 使用场景

- 用户输入 `/yy-mode-plan` 命令
- 用户希望在实施变更前先制定计划

不应触发：

- 用户直接要求执行某个任务，未提及计划
- 用户只是询问项目信息

## 指令

### 1. 理解需求

分析用户需求，判断任务复杂度：

- **简单需求**：可直接在对话中输出计划
- **复杂需求**：创建计划文件

### 2. 制定计划

根据需求制定计划，包含以下要素：

- 目标：明确说明将要完成的内容
- 方法：高层策略
- 步骤：有序的实施步骤列表，**核心步骤需细化具体实现方式**
- 涉及文件：将要修改的文件列表
- 风险：潜在问题及应对策略
- 代码示例：核心逻辑片段

**细化原则**：只细化核心步骤的实现方式，不细化所有细节。核心步骤是指对结果有关键影响的步骤。

### 3. 展示计划

向用户展示计划内容，等待确认。

### 4. 处理用户反馈

- **用户确认**：开始执行计划
- **用户拒绝**：根据反馈调整计划，重新展示

### 5. 执行计划

用户确认后：

1. 更新/创建待办事项列表
2. 按步骤执行计划
3. 仅在计划完全完成时终止

## 计划文件位置

### 目录选择优先级

1. **用户手动指定**（最高优先级）
   - 格式：`--tool-dir <目录> --plan-file <文件名>`
2. **自动检测**：按 `.agents` > `.claude` > `.opencode` > `.trae` 顺序检测
3. **无匹配目录**：提示用户指定或创建

### 目录结构

```text
{项目根目录}/
└── {工具目录}/
    └── plans/
        └── {时间戳}_{计划文件名}.md
```

时间戳格式：`YYYYMMDD_HHMMSS`，如 `20260324_153045_用户认证系统.md`。

## 输出格式

- 必须展示计划内容
- 必须等待用户确认
- 复杂需求必须说明计划文件路径

## 相关资源

本技能包含以下辅助资源：

- `examples/input.md`：输入示例，展示用户如何请求制定计划
- `examples/output.md`：输出示例，展示计划文件的预期格式
