# 技能基础模板

## 模板结构

```markdown
---
name: skill-name
description: >
  精确描述技能做什么以及何时使用。必须是单一、清晰的任务边界。
  包含触发条件说明。
---

## When to use
- 用户要求 X 时
- 涉及 Y 上下文时
- 触发条件 3

## Don't use when
- 用户要求直接实现新功能时
- 简单的 Z 操作时
- 不应触发的场景 3

## Steps
1. 第一步：描述做什么，为什么
2. 第二步：描述下一步操作
3. 第三步：继续描述后续步骤
4. 最后一步：输出结果

## Output contract
- 输出项 1：描述
- 输出项 2：描述
- 输出项 3：描述
```

## 命名规范

| 类型 | 格式 | 示例 |
|------|------|------|
| 技能目录 | kebab-case | `create-skill/` |
| 技能名称 | kebab-case，动宾结构，名词单数 | `create-rule`、`read-pdf` |
| 脚本文件 | snake_case | `lint.mts` |
| 参考文档 | kebab-case | `references/schemas.md` |

## 编写原则

### YAML Frontmatter

**关键规则：**

- 使用 `>`（折叠式）处理长段落 - 换行符转换为空格
- 使用 `|`（保留式）处理代码块或列表 - 保留换行符
- **禁止**将长描述放在键的同一行

```yaml
# ❌ 错误 - 可能导致解析错误
description: 这是一个很长的描述，超过了...

# ✅ 正确
description: >
  这是一个很长的描述，使用折叠样式。
  换行符会转换为空格。
```

### Description 编写

- **精确性**：明确定义技能的单一任务边界
- **路由性**：包含触发条件，避免误触发
- **简洁性**：控制在 2-3 句话内

```yaml
# ❌ 太宽泛
description: Review code

# ✅ 精确
description: >
  审查 PR 的逻辑正确性、安全风险、测试覆盖缺口。
  仅用于审查，不用于直接改代码。
```

### Don't use when

必须定义明确的负例条件，防止误调用：

- 列出不应触发的典型场景
- 与 When to use 形成互补
- 帮助 AI 理解技能边界

### 输出格式

- 必须固定格式，便于自动化评测
- 列出所有输出项及其含义
- 复杂结构使用嵌套格式

```markdown
## Output contract
- Critical: 严重风险列表
- High: 高风险列表
每条包含：位置、触发条件、后果、修复建议
```

## 质量要求

- **长度控制**：SKILL.md 应控制在 500 行以内，超出内容移至 references
- **语言风格**：使用祈使语气（"做 X"），使用中文描述
- **代码示例**：包含语言标签
- **模块化**：通用规范移至通用文档，避免每个技能重复
