# 技能编写指南

本文档提供技能模板的填写规范和编写原则。

## 模板结构

```markdown
---
name: 技能名称
description: 简要描述这个技能的功能和使用场景
---

# 技能名称

## 描述

**必须包含此章节**。用 1-2 句话描述技能的核心作用，帮助 AI 理解技能用途。

```markdown
## 描述

在提交代码前自动格式化代码，确保代码风格一致。
```

## 使用场景

描述触发这个技能的条件，包括应该触发和不应触发的场景。

## 指令

清晰的分步说明，告诉智能体具体怎么做。最后一步描述输出格式。

## 示例 (可选)

输入/输出示例，展示预期效果。

```text
（示例内容）
```

## 命名规范

- 技能目录：kebab-case（如 `create-skill/`）
- 技能名称：kebab-case，动宾结构，名词单数（如 `create-rule`、`read-pdf`）
- 脚本文件：snake_case（如 `lint.mts`）
- 参考文档：kebab-case（如 `resources/schemas.md`）

## 编写原则

### YAML Frontmatter

**关键规则：**

- 使用 `>`（折叠式）处理长段落 - 换行符转换为空格
- 使用 `|`（保留式）处理代码块或列表 - 保留换行符
- **禁止**将长描述放在键的同一行

```yaml
# ❌ 错误 - 可能导致解析错误
description: 这是一个很长的描述，超过了...

# ✅ 正确
description: >
  这是一个很长的描述，使用折叠样式。
  换行符会转换为空格。
```

### Description 编写

- **精确性**：明确定义技能的单一任务边界
- **路由性**：包含触发条件，避免误触发
- **简洁性**：控制在 2-3 句话内

```yaml
# ❌ 太宽泛
description: Review code

# ✅ 精确
description: >
  审查 PR 的逻辑正确性、安全风险、测试覆盖缺口。
  仅用于审查，不用于直接改代码。
```

### 使用场景

必须定义明确的触发条件和不应触发的场景：

- 列出应该触发的典型场景
- 列出不应触发的典型场景
- 帮助 AI 理解技能边界

```markdown
## 使用场景
- 用户提到"格式化代码"、"代码格式化"
- 用户要在提交前整理代码格式

不应触发：
- 用户只是查看代码
- 用户要求重构代码逻辑
```

### 指令

清晰的分步说明，每一步描述具体操作：

- 使用祈使语气（"做 X"）
- 每一步只描述一个操作
- 最后一步描述输出格式

```markdown
## 指令
1. 检测项目使用的语言和格式化工具
2. 运行相应的格式化命令
3. 输出格式化结果：工具名称、处理文件数、变更摘要
```

## 质量要求

- **长度控制**：SKILL.md 应控制在 500 行以内，超出内容移至 resources
- **语言风格**：使用祈使语气（"做 X"），使用中文描述
- **代码示例**：包含语言标签
- **模块化**：通用规范移至通用文档，避免每个技能重复

## 路径格式规范

- 使用正斜杠作为路径分隔符，路径包含空格时使用引号包裹，以确保跨平台兼容性和正确解析
