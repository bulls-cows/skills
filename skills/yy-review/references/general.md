# 通用审核规则

## 使用原则

- 优先关注本次改动引入、放大或未收敛的问题
- 优先使用可跨项目复用的工程原则，不把单个项目的习惯直接当成通用阻断项
- 只有在项目约定已经形成明确契约、并且本次改动触发了该契约时，才按项目约定报告问题
- 所有问题都要说明可验证影响，不因个人偏好、代码风格偏好或 UI 审美偏好直接报问题

## 审查维度

- 正确性与安全性：语法、类型、运行时行为、权限校验、注入风险、敏感信息暴露
- 契约一致性：接口、类型、Schema、序列化结构、状态字段、返回格式、分页字段、错误码等是否前后一致
- 分层与职责边界：展示层、路由层、控制层、服务层、数据层、工具层职责是否混杂，是否把应下沉的复杂度外抛给调用方
- 数据与查询可靠性：输入校验、空值处理、边界条件、分页、聚合、并发更新、事务、批量操作、N+1 查询、重复请求
- 异步与错误处理：异常是否被吞掉，Promise 是否正确等待，失败分支是否收敛，状态是否回滚或复位
- 关联变更完整性：新增或调整页面、接口、路由、菜单、配置、类型、文档、导航、导出项时，相关入口和依赖是否同步更新
- 可维护性与可演进性：命名是否表达真实语义，重复逻辑是否提取，复杂分支是否可读，可复用能力是否被硬编码分叉替代

## 严重

- 语法与类型错误：语法结构错误、未定义变量、明显类型不匹配、未闭合标签或括号
- 运行时逻辑错误：空指针、数组越界、错误分支、状态更新顺序错误、异步竞态、死循环、资源未释放
- 安全风险：XSS、SQL 注入、命令注入、路径穿越、SSRF、敏感信息泄露、不安全反序列化、缺失关键权限校验
- 契约破坏：接口参数、返回结构、状态枚举、分页字段、错误语义或持久化字段含义被修改，但上下游未同步
- 数据破坏风险：错误删除、覆盖更新、批量操作范围失控、事务缺失导致部分成功、并发写入导致脏数据

## 中等

- 输入校验与边界处理不足：空值、异常输入、分页边界、时间边界、非法状态、默认值缺失、类型转换不完整
- 错误处理与异步流程缺陷：Promise 未处理、异常吞掉、失败分支未终止、加载状态未复位、重复请求风险、重试与兜底缺失
- 分层与职责越界：路由层、控制层、服务层、数据层、组件层、工具层职责混杂，导致逻辑重复、复用困难或测试困难
- 查询与性能隐患：N+1 查询、无必要串行请求、计数与列表查询耦合错误、批量操作仍逐项请求、明显重复计算
- 关联变更不完整：新增或调整页面、接口、路由、菜单、配置、导出项、类型、文档后，必要入口或依赖未同步
- 可维护性与最佳实践：重复代码、复杂条件、过度嵌套、命名无法表达语义、死代码、无效抽象、硬编码分叉替代配置或映射
- Early return：优先使用提前返回避免深层嵌套；若深层嵌套已明显影响可读性或遗漏异常分支，可作为中等问题报告

## 轻微

- 调试代码与低风险风格问题：`console.log`、`debugger`、临时注释、格式轻微不一致
- 表达不清但未直接影响行为：变量名过短、注释滞后、局部结构可读性较差、提取复用机会明显但风险较低
- 项目约定偏差但未形成行为风险：命名、目录、导入顺序、轻量文案或样式约定不一致，且未破坏契约
