# yy-review

## 描述

对 git 变动文件进行代码审核，按严重程度分类输出问题描述和修复建议。

## 使用场景

- 用户要求审核代码、代码 review、代码检查
- 用户提到"审核改动"、"review 代码"、"检查代码质量"
- 提交前检查、合并前审核、PR 审核

不应触发：

- 用户要求直接修改代码（应使用其他优化技能）
- 用户只是询问某个代码问题
- 用户要求生成 git 提交信息

## 指令

### 1. 获取改动文件列表

使用 git 命令获取改动的文件：

```bash
git diff --name-only HEAD
```

对于暂存的文件：

```bash
git diff --cached --name-only
```

过滤出代码文件，排除自动生成的文件和配置文件。

**决策分支**：

- **存在改动文件**：进入步骤 2
- **无改动文件**：提示用户当前没有代码改动，退出执行

### 2. 代码审核

对每个改动的文件进行以下检查：

**语法错误检查**：

- 未闭合的标签
- 未定义的变量
- 语法结构错误

**逻辑错误检查**：

- 空指针引用
- 数组越界风险
- 逻辑判断错误

**安全漏洞检查**：

- XSS 风险
- 敏感信息泄露
- SQL 注入风险（模板字符串拼接 SQL 时）

**最佳实践检查**：

- console.log/debugger 等调试代码
- 硬编码的敏感信息
- 不必要的注释或死代码

**决策分支**：

- **catch 块中的 console.warn**：不视为问题
- **其他位置的 console.log/debugger**：标记为轻微问题

### 3. 输出审核结果

**决策分支**：

- **无问题**：输出审核通过格式
- **只有轻微问题**：输出审核结果，提示存在轻微问题
- **有严重或中等问题**：输出审核结果，等待用户修复后重新审核

输出格式：

```markdown
## 审核结果

### 问题统计

- 审核文件数：N
- 严重：X 个
- 中等：Y 个
- 轻微：Z 个

### 问题详情

#### 文件: [filename]

1. **[严重/中等/轻微]** - [问题类型] - [问题描述]
   - 位置: 第 N 行
   - 代码: `xxx`
   - 建议: [修复建议]
```

**审核通过格式**：

```markdown
## 审核结果

代码审核通过！未发现严重或中等问题。

### 审核统计

- 审核文件数：N
- 发现问题：0 个
```

## 安全边界

**禁止主动执行的命令**：

- 编译命令、构建命令、部署命令
- 自动执行的测试命令
- 任何会修改代码的命令
