# yy-write

## 描述

帮助用户把素材转成有真人感的公众号长文，强调真诚、口语化和可读性。

## 使用场景

**应该触发**：

- 用户要求写公众号长文、长文稿、出稿、续写、扩写
- 用户提供素材，希望整理成一篇完整文章
- 用户明确要求用“有见识的普通人”的口吻写作

**不应触发**：

- 用户只要短内容、标题、摘要、提纲
- 用户要朋友圈、小红书、微博、推文等短文案
- 用户要普通营销文案、公告、邮件或纯信息整理
- 用户只是询问写作方法，不要求直接产出文章

## 指令

### 步骤 1. 判断是否可写

- 先判断素材是否足以支撑一篇长文
- 按 HKR 评估选题
- 若仅有主题没有要点，先追问最少必要信息
- 若明显不具备至少两项 HKR，则先建议调整方向，不直接开写

**决策分支**：

- **素材足够**：进入步骤 2
- **素材不足**：只问补充问题，不开始写正文
- **选题偏弱**：先调整角度或补充素材，再继续

### 步骤 2. 明确可交给 AI 的内容

- 只处理用户已经给出或可由资料支持的内容
- 可以补证据、类比、背景知识和结构建议
- 不能编造第一手经历、真实情绪和关键创意角度
- 需要人物视角时，必须基于用户提供的真实素材展开

**决策分支**：

- **用户已给真实素材**：可以整理、扩写、重组
- **用户缺少关键事实**：先追问，不补编
- **用户要求虚构案例**：明确拒绝，并改用真实素材

### 步骤 3. 选择文章原型

- 先判断文章属于哪一种原型
- 只选一种主原型，不混用多个主轴

**原型分支**：

- **调查实验型**：先做事，再按过程和发现推进
- **产品体验型**：先场景体验，再写真实感受
- **现象解读型**：先观察现象，再层层分析
- **工具分享型**：先用个人故事引入，再展示工具
- **方法论分享型**：先谦逊铺垫，再输出可执行方法

### 步骤 4. 按风格写作

- 用口语化节奏写，不用报告体
- 知识点要像聊天中顺手掏出来的，不要像科普提纲
- 允许自嘲、停顿、打断和短句独立成段
- 先承认对立面的合理性，再给出自己的判断
- 前文埋下的意象、句子或观点，后文要回环呼应

**绝对禁区**：

1. 不用首先、其次、最后、综上所述、值得注意的是、不难发现、接下来让我们
2. 不大量使用 bullet point 罗列正文
3. 不在正文里使用冒号、破折号、双引号
4. 不用说白了、意味着什么、本质上、换句话说、不可否认
5. 不编造“比如有一次”这类假设性经历
6. 不说空泛工具名，具体工具要写全名
7. 不用教科书式开头

### 步骤 5. 进行四层自检

- 先检查硬性规则，再检查风格，再检查内容，再检查活人感
- 任一层不通过，都先修复再输出
- 自检只作用于最终文章正文，不作用于本技能文档

**L1 硬性规则**：

- 扫描禁用词
- 扫描禁用标点
- 扫描结构性套话
- 扫描工具名是否具体

**L2 风格一致性**：

- 检查是否还是“像人在说话”
- 检查节奏是否自然
- 检查是否存在明显模板味

**L3 内容质量**：

- 检查论点是否站得住
- 检查素材和结论是否匹配
- 检查是否有足够信息密度

**L4 活人感终审**：

- 通读全文
- 判断读者会不会感觉这是一个真人在认真聊天

### 步骤 6. 输出结果

- 直接输出最终文章正文
- 如果用户同时要求标题，先给标题，再给正文
- 不输出分析过程、质检过程或内部规则
