# yy-create-prd

## 描述

帮助用户创建或更新 AI 全栈 Web 项目的 PRD 产品需求文档，基于项目实际技术栈和功能规划，生成结构完整的产品需求文档。

## 使用场景

- 用户提到"创建 PRD"、"生成需求文档"、"撰写产品需求"
- 用户要求"生成 XX 项目的 PRD"、"为 XX 功能写需求文档"
- 用户要求"补充 PRD"、"更新 PRD"、"完善需求文档"

不应触发：

- 用户要求生成 API 文档、接口设计文档
- 用户要求生成代码注释、技术方案文档
- 用户仅要求审查或审核现有 PRD

## 指令

### 步骤 1. 识别任务类型

**决策分支**：

- **用户指定了 PRD 文件路径**：进入步骤 2（更新模式）
- **用户未指定文件路径**：进入步骤 2（创建模式）

### 步骤 2. 收集项目信息

根据任务类型选择信息收集方式：

**创建模式**：

- 了解目标项目名称和定位
- 了解核心功能需求（可追问用户，或从项目结构推断）
- 了解技术栈限制（如：不使用 Element Plus、使用 ChromaDB 而非 Milvus 等特殊约束）
- 了解迭代优先级（哪些功能先做，哪些后做）

**更新模式**：

- 读取现有 PRD 文件内容
- 了解用户需要补充或修改的内容
- 确认修改范围（全量更新 / 部分章节更新）

### 步骤 3. 确定 PRD 章节结构

根据项目类型选择需要包含的章节，PRD 标准章节包括：

**必含章节**（每个 PRD 都必须有）：

- 产品概述（定位、目标用户、核心价值）
- 功能架构（整体功能模块图）
- 核心功能详细需求
- 技术架构（后端/前端技术栈）
- 迭代路线图（Phase 分阶段规划）

**可选章节**（根据项目实际需求选择）：

- 竞品分析
- 数据模型设计
- 接口设计
- 非功能需求（性能、安全、可扩展性）
- 术语表
- 参考资料

### 步骤 4. 生成 PRD 内容

使用 `templates/prd-template.md` 作为基础模板，按以下规则填充内容：

**技术栈描述规范**：

- 后端框架注明技术栈名称和版本（如 Express + TypeScript）
- 数据库选型需注明是 MySQL 还是 PostgreSQL，以及使用的向量数据库（如 ChromaDB/Milvus/pgvector）
- 不使用 Element Plus 等用户明确禁止的组件库
- 消息队列、缓存等技术按实际情况描述

**功能描述规范**：

- 每个功能包含：功能名称、输入、输出、核心流程、边界情况
- AI 相关功能需注明：是否涉及 RAG、Embedding、流式输出、工具调用等
- 重计算任务（如 Embedding 生成、向量化）需注明执行位置（服务器 / 本地消费者）

**迭代路线图规范**：

- 按 Phase 1/2/3 分阶段，每阶段标注预计工作量
- Phase 1 优先放核心功能（优先级最高、工程价值最大的）

### 步骤 5. 输出文件

**创建模式**：

- 在用户指定目录下生成 `{项目名}-prd.md` 文件
- 文件编码：UTF-8
- 表格使用 Markdown 标准表格语法

**更新模式**：

- 读取现有文件，确认修改位置
- 按用户要求进行局部修改或全量重写
- 修改后保持原有文档结构和格式一致

### 步骤 6. 展示结果

向用户展示：

- 生成/更新的文件路径
- 文档包含的主要章节列表
- 关键决策点（如技术选型、优先级判断）的说明
- 待用户确认或补充的内容

## 安全边界

- 不修改用户未指定的文件
- 不在 PRD 中编造未经验证的技术细节
- 不强制要求用户接受特定技术选型，仅在 PRD 中如实记录用户决策
