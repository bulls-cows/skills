# yy-git-commit-directly

## 描述

本技能在 `yy-git-commit` 基础上跳过提交前确认，直接暂存并提交当前工作区的所有可提交改动。未特别说明的逻辑均复用 `yy-git-commit`。

## 使用场景

- 用户说"无需确认直接提交所有改动"
- 用户说"直接 commit 所有改动"
- 用户说"自动提交当前全部变更"
- 用户点名调用 `yy-git-commit-directly`
- 用户明确要求提交且同时表达"不需要确认"

不应触发：

- 用户只想生成提交信息但不提交
- 用户只想查看 Git 状态或历史
- 用户只想暂存文件或执行 `git add`
- 用户要求执行 git push、pull、merge 等其他操作
- 用户要求修改代码或实现功能

## 指令

### 步骤 1. 确认直接提交前提

用户点名调用本技能时，视为已经表达"提交当前工作区所有可提交改动，并跳过提交前确认"的授权，不再要求用户重复说明。

**决策分支**：

- **用户点名调用本技能**：视为同时具备提交意图和免确认授权，继续执行后续步骤
- **用户未点名调用本技能，但明确要求无需确认、直接提交或自动提交所有改动**：继续执行后续步骤
- **用户未点名调用本技能，且只表达普通提交意图**：停止本技能流程，不按免确认方式提交
- **用户明确要求只生成提交信息、只查看状态、只暂存或执行非提交 Git 操作**：停止本技能流程，不执行提交

### 步骤 2. 执行 yy-git-commit 流程（免确认模式）

复用 `yy-git-commit` 的完整提交流程，并应用以下覆盖规则：

**暂存范围覆盖**：默认将 `git status` 列出的所有可提交改动纳入暂存，不要求用户指定文件。用户明确要求排除时从候选中移除。

**分次提交覆盖**：若 `yy-git-commit` 判断应分次提交，直接按拆分方案逐组执行，每组跳过确认。若某组提交失败，停止后续分组。

**确认步骤覆盖**：执行到 `yy-git-commit` 的展示并确认步骤时，跳过交互确认，直接进入执行。但仍展示暂存文件列表、关键变更摘要和提交信息，供用户事后核验。

**敏感文件处理覆盖**：`yy-git-commit` 对敏感命名特征文件仅展示警告（因有确认步骤兜底）；本技能无确认步骤，因此发现凭证、私钥或高风险敏感文件时停止提交并说明原因。

### 步骤 3. 输出结果

提交完成后，输出以下内容：

1. 提交的文件列表
2. 提交信息
3. 提交哈希值
4. 若提交未执行，说明阻塞原因和建议处理方式

## 安全边界

复用 `yy-git-commit` 的安全边界，并叠加以下覆盖：

- 发现凭证、私钥或高风险敏感文件时停止提交（覆盖 `yy-git-commit` 的仅警告策略，因本技能无确认步骤兜底）
- 禁止在未点名调用本技能且无提交意图或无免确认意图时按本技能执行
