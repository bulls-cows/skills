# yy-git-commit-directly

## 描述

本技能用于在用户点名调用本技能，或明确授权“无需确认直接提交所有改动”时，间接调用 `yy-git-commit` 技能完成提交。

核心目标：

1. 复用 `yy-git-commit` 的改动分析、提交信息生成和提交执行流程
2. 跳过提交前的二次确认步骤
3. 直接暂存并提交当前工作区的所有可提交改动

## 使用场景

- 用户说“无需确认直接提交所有改动”
- 用户说“直接 commit 所有改动”
- 用户说“自动提交当前全部变更”
- 用户点名调用 `yy-git-commit-directly`
- 用户明确要求提交且同时表达“不需要确认”

不应触发：

- 用户只想生成提交信息但不提交
- 用户只想查看 Git 状态或历史
- 用户只想暂存文件或执行 `git add`
- 用户要求执行 git push、pull、merge 等其他操作
- 用户要求修改代码或实现功能

## 指令

### 步骤 1. 确认直接提交前提

用户点名调用本技能时，视为已经表达“提交当前工作区所有可提交改动，并跳过提交前确认”的授权，不再要求用户重复说明“直接提交所有改动”。

**决策分支**：

- **用户点名调用本技能**：视为同时具备提交意图和免确认授权，继续执行后续步骤
- **用户未点名调用本技能，但明确要求无需确认、直接提交或自动提交所有改动**：继续执行后续步骤
- **用户未点名调用本技能，且只表达普通提交意图**：停止本技能流程，不按免确认方式提交
- **用户明确要求只生成提交信息、只查看状态、只暂存或执行非提交 Git 操作**：停止本技能流程，不执行提交

### 步骤 2. 调用 yy-git-commit 流程

优先复用 `yy-git-commit` 技能的完整提交流程，包括：

1. 分析当前 Git 状态和变更内容
2. 理解改动意图
3. 生成规范提交信息
4. 执行暂存与提交

**调用要求**：

- 若用户点名调用本技能但未附加说明，将用户意图补充为“无需确认直接提交所有改动”
- 将文件选择策略补充为“提交当前工作区的所有可提交改动”
- 保留 `yy-git-commit` 对凭证、私钥、冲突、无变更和异常状态的安全处理规则
- 不执行 git push、pull、merge、rebase、amend 或强制操作

### 步骤 3. 跳过提交前确认

执行到 `yy-git-commit` 的提交确认阶段时，不再向用户展示“是否确认提交”的交互问题。

**决策分支**：

- **已生成提交信息且可提交文件列表有效**：直接执行暂存和提交
- **发现凭证、私钥或高风险敏感文件**：停止提交并说明原因，不绕过安全边界
- **发现合并冲突或异常 Git 状态**：停止提交并说明需先处理的问题
- **当前工作区没有可提交改动**：停止提交并说明没有变更

### 步骤 4. 输出结果

提交完成后，输出以下内容：

1. 提交的文件列表
2. 提交信息
3. 提交哈希值
4. 若提交未执行，说明阻塞原因和建议处理方式

## 安全边界

- 禁止执行 `git push`、`git pull`、`git merge`、`git rebase`、`git commit --amend` 或强制操作
- 禁止使用 `--no-verify` 跳过项目 hook
- 禁止提交凭证、私钥或明确敏感文件
- 禁止在存在合并冲突时继续提交
- 禁止在未点名调用本技能且无提交意图或无免确认意图时按本技能执行

## 路径格式规范

- 在文档中提及文件路径时，优先使用相对路径
- 在终端中提及文件路径时，优先使用绝对路径
- 使用正斜杠作为路径分隔符，路径包含空格时使用引号包裹
