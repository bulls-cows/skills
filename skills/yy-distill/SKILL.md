# yy-distill

从用户指定的内容中分析并提炼核心特质。

## 描述

从用户指定的内容中分析并提炼核心性格特质，构建思维操作系统。

## 使用场景

- 用户想要分析自己的风格（不限于开发风格）
- 用户想要提炼个人特质
- 用户想要生成个人画像
- 用户想要理解他人的思维风格

不应触发：

- 用户只是查看内容
- 用户要求统计数量
- 用户要求分析其他人的内容（除非提供了该人的内容）

## 指令

### 1. 确定分析来源

**必须要求用户提供分析来源**。

如果用户未提供来源，询问用户希望分析什么内容。

可接受的内容形式：

- 文件路径（单个文件或目录）
- 文本内容（直接粘贴）
- URL（博客、文章等）
- 代码仓库

### 2. 多维度信息采集

从以下六个维度分析内容：

#### 2.1 内容类型分析

识别主要内容类型及其比例：

- 主要内容形式是什么？
- 类型分布如何？
- 关注重点是什么？
- 表达偏好是什么？

#### 2.2 高频概念分析

识别反复出现的概念：

- 核心关注点是什么？
- 价值取向如何？
- 思维习惯是什么？
- 反复出现的动词和名词有哪些？

#### 2.3 决策痕迹分析

识别选择、取舍、判断的痕迹：

- 决策逻辑是什么？
- 优先级如何排序？
- 权衡方式是什么？
- 风险态度如何？

#### 2.4 表达方式分析

分析语言风格和结构：

- 句式偏好是什么？（长句/短句、疑问/陈述）
- 词汇特征有哪些？（高频词、专属术语、禁忌词）
- 节奏感如何？（先结论还是先铺垫、转折方式）
- 确定性表达如何？（「我不确定」型还是「很明显」型）

#### 2.5 互动模式分析

分析与他人/内容的互动：

- 沟通风格是什么？
- 反馈方式如何？
- 开放性如何？

#### 2.6 时间线分析

分析内容的时间分布：

- 持续性如何？
- 变化趋势是什么？
- 成长轨迹如何？

### 3. 三重验证机制

对每个候选特质进行三重验证：

#### 验证1: 跨域复现

特质是否在多个不同场景/类型的内容中出现？

- 是 → 继续验证
- 否 → 降级为观察，不作为核心特质

#### 验证2: 有生成力

能否推断在面对新情况时的可能反应？

- 能 → 继续验证
- 不能 → 降级为描述，不作为预测性特质

#### 验证3: 有排他性

是否不是所有人都会这样？是否体现独特性？

- 是 → 确认为核心特质
- 否 → 降级为共性，不作为个人特质

**验证结果处理**：

- 三重通过 → 核心特质
- 两重通过 → 次要特质
- 一重通过 → 观察记录
- 零重通过 → 不纳入

### 4. 提炼特质

从人的性格特质角度提炼，而非操作层面：

- **应该**：使用"追求本质""系统化思考""长期主义"等性格特质
- **不要**：使用"DRY 原则践行者""结构化思维"等操作描述

提炼原则：

1. 每条特质用一句话概括，包含特质名称和具体表现
2. 基于内容证据，不做主观臆断
3. 从"为什么这么做"的角度理解，而非"做了什么"
4. 输出结果不涉及具体原始内容，使用抽象概括，不引用具体文件名、代码、提交信息等

### 5. 输出结果

以结构化格式输出提炼结果：

```markdown
## 核心特质

### 特质1: [名称]
**一句话**：[最简描述]
**证据**：[至少2个不同场景的具体证据]
**应用**：[在什么情况下会体现这个特质]
**局限**：[这个特质在什么情况下可能不适用]

### 特质2: [名称]
...

## 决策偏好

[在面临选择时的倾向：优先级、权衡方式、风险态度等]

## 表达DNA

[表达风格特征：句式、词汇、节奏、确定性等]

## 诚实边界

此提炼基于有限内容，存在以下局限：
- 基于有限内容推断，可能存在偏差
- 公开表达与真实想法可能存在差距
- 特质可能随时间变化
- 无法捕捉直觉和隐性知识
- 信息来源的可信度影响结果准确性

- 分析时间：[日期]
- 内容数量：[数量]
- 内容类型：[类型]
```

## 示例

### 输入

```text
分析 skills/ 目录下的技能文件，提炼我的核心特质
```

### 输出

```markdown
## 核心特质

### 特质1: 追求本质
**一句话**：不喜欢形式主义，关注事物的核心价值，倾向删繁就简
**证据**：
- 技能描述简洁明了，避免冗余修饰
- 代码风格偏好简单直接的实现
- 文档结构清晰，重点突出
**应用**：在面对复杂问题时，会本能地寻找最简单的解决方案
**局限**：可能忽略形式的重要性，在某些需要仪式感的场景下不够敏感

### 特质2: 系统化思考
**一句话**：有构建体系的习惯，修改不是零散的，而是为了整体一致性
**证据**：
- 技能之间存在清晰的关联和层次
- 修改时考虑对整体的影响
- 文档结构遵循统一的规范
**应用**：在解决问题时，会考虑问题的上下文和长期影响
**局限**：可能过度追求系统化，导致行动迟缓

### 特质3: 长期主义
**一句话**：愿意为未来投入，建立规范、重构结构，不只是解决当下问题
**证据**：
- 建立了完整的规范体系
- 投入时间优化基础设施
- 文档和代码都考虑未来的可维护性
**应用**：在决策时会考虑长期价值，而非短期收益
**局限**：可能错过短期机会，在需要快速迭代的场景下不够灵活

### 特质4: 知识复用
**一句话**：有记录经验的习惯，希望后续也能遵循同样思路
**证据**：
- 创建了多个技能记录工作流程
- 文档详细记录决策过程
- 建立了规则和最佳实践
**应用**：在解决问题后，会总结经验并记录，便于复用
**局限**：可能过度依赖既有经验，在面对新问题时不够开放

## 决策偏好

- **优先级**：质量 > 速度，长期 > 短期，系统 > 局部
- **权衡方式**：先考虑整体影响，再做局部决策
- **风险态度**：偏好可控的风险，避免不可逆的决策

## 表达DNA

- **句式**：短句为主，陈述式为主，少量疑问句
- **词汇**：高频词：核心、本质、系统、规范、长期
- **节奏**：先结论后展开，层次分明
- **确定性**：适度确定，避免绝对化表达

## 诚实边界

此提炼基于有限内容，存在以下局限：
- 基于有限内容推断，可能存在偏差
- 公开表达与真实想法可能存在差距
- 特质可能随时间变化
- 无法捕捉直觉和隐性知识
- 信息来源的可信度影响结果准确性

- 分析时间：2026-05-10
- 内容数量：10+ 技能文件
- 内容类型：技能文档、规则文档
```
