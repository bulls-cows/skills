# yy-distill

## 描述

从用户指定的内容中分析并提炼思维方式，包括思维模式、决策逻辑、认知习惯和知识组织方式。

## 使用场景

- 用户想要分析思维模式
- 用户想要识别决策逻辑
- 用户想要挖掘认知习惯
- 用户想要理解思考框架

不应触发：

- 用户只是查看内容
- 用户要求统计数量
- 用户要求分析其他人的内容（除非提供了该人的内容）
- 用户仅需要分析性格特质而非思维方式

## 指令

### 1. 确定分析来源

**必须要求用户提供分析来源**。

如果用户未提供来源，询问用户希望分析什么内容。

可接受的内容形式：

- 文件路径（单个文件或目录）
- 文本内容（直接粘贴）
- URL（博客、文章等）
- 代码仓库

### 2. 多维度信息采集

从以下六个维度分析思维方式：

#### 2.1 思维模式识别

分析问题拆解和思考方式：

- 问题拆解习惯：自上而下还是自下而上？先框架还是先细节？
- 抽象层次偏好：倾向于具体实例还是抽象概念？
- 假设前提识别：隐含的前提假设是什么？
- 思维路径：从问题到结论的推导过程如何？

#### 2.2 决策逻辑分析

识别决策依据和判断方式：

- 决策依据：优先考虑什么因素？
- 优先级排序：如何确定重要性？
- 权衡方式：如何在冲突目标间取舍？
- 验证机制：如何确认判断的正确性？

#### 2.3 认知习惯挖掘

分析信息处理和学习方式：

- 信息获取：倾向于主动探索还是被动接收？
- 验证习惯：如何验证信息的可靠性？
- 纠错模式：发现错误时如何处理？
- 学习偏好：通过什么方式吸收新知识？

#### 2.4 知识组织方式

分析知识分类和关联方式：

- 分类习惯：如何组织和归类信息？
- 关联方式：如何建立知识间的联系？
- 复用策略：如何复用已有知识和经验？
- 存储偏好：倾向于结构化还是零散存储？

#### 2.5 表达逻辑结构

分析论证和表达的思维结构：

- 论证方式：演绎、归纳、类比还是其他？
- 证据使用：如何选择和使用证据？
- 叙事结构：线性、分支还是其他结构？
- 逻辑严密性：论证的完整性和一致性如何？

#### 2.6 演变轨迹追踪

分析思维方式的变化趋势：

- 持续性：思维方式是否保持一致？
- 变化趋势：思维方式如何演进？
- 触发因素：什么导致思维方式变化？
- 成长模式：思维能力如何提升？

### 3. 三重验证机制

对每个候选思维方式进行三重验证：

#### 验证1: 跨域一致性

思维方式是否在不同问题场景下保持一致？

- 是 → 继续验证
- 否 → 降级为观察，不作为核心思维方式

#### 验证2: 有预测力

能否推断在新问题上的思维路径和决策方式？

- 能 → 继续验证
- 不能 → 降级为描述，不作为预测性思维方式

#### 验证3: 有独特性

是否体现独特的思维模式而非通用做法？

- 是 → 确认为核心思维方式
- 否 → 降级为共性，不作为独特思维方式

**验证结果处理**：

- 三重通过 → 核心思维方式
- 两重通过 → 次要思维方式
- 一重通过 → 观察记录
- 零重通过 → 不纳入

### 4. 提炼思维方式

从思维模式角度提炼，而非操作层面：

- **应该**：使用"自上而下拆解问题""先验证假设再行动""通过类比建立关联"等思维模式描述
- **不要**：使用"DRY 原则践行者""代码写得好"等操作或结果描述

提炼原则：

1. 每条思维方式用一句话概括，包含名称和具体表现
2. 基于内容证据，不做主观臆断
3. 从"如何思考"的角度理解，而非"做了什么"

#### 避免套模板（重要）

**严禁照搬示例中的思维方式名称和描述**。示例仅供参考输出格式，思维方式内容必须从实际分析数据中提炼。

错误做法：

- 直接使用示例中的"自上而下拆解问题""先验证假设再行动"等思维方式名称
- 套用示例中的证据描述
- 输出与示例高度相似的思维方式组合

正确做法：

- 从实际数据中识别独特的思维模式
- 用自己的语言命名和描述思维方式
- 确保证据来自分析内容，而非示例
- 如果分析结果与示例相似，应反思是否真正基于数据提炼

**自检方法**：输出前对照示例，检查思维方式名称是否雷同。如果超过一半的思维方式名称与示例相同，需要重新分析数据。

#### 隐私保护原则（重要）

输出结果必须遵循以下隐私保护原则：

1. **不引用原文**：不要直接引用或复述输入内容中的具体文本
2. **不暴露细节**：不要提及具体的文件名、代码片段、提交信息、人名、具体数值等
3. **抽象概括**：将具体行为抽象为一般性描述
4. **证据抽象化**：证据部分使用抽象化后的描述，而非原始内容

错误示例（暴露隐私）：

- "大量'移除'、'简化'、'删除'类提交"
- "如'移除未使用的导入'、'简化 lint 脚本逻辑'"
- "提交类型分布：feat (852)、refactor (549)"
- "主要贡献者：张三 (57%)、李四 (39%)"

正确示例（抽象概括）：

- "频繁进行代码简化相关的操作"
- "倾向于移除冗余代码和配置"
- "提交类型以功能开发和重构为主"
- "由少数核心贡献者主导"

### 5. 输出思维方式分析报告

按照以下结构输出分析结果：

#### 输出格式结构

- **数据概览**（可选）：分析来源的基本统计信息
- **核心思维方式**（必选）：含定义、证据、三重验证结果
- **次要思维方式**（可选）：未通过完整验证但有价值的观察
- **思维方式关联图谱**（可选）：思维方式之间的因果关系
- **思维路径预测**（可选）：基于思维方式预测在新问题上的思考路径
- **总结**（必选）：思维方式组合的整体概括
- **说明**（必选）：隐私说明和局限性分析

#### 思维方式描述格式

每个思维方式包含以下要素：

- **定义**：一句话概括思维方式含义
- **证据**：从分析内容中提取的抽象化证据（2-4 条）
- **验证**：三重验证结果（跨域一致性、有预测力、有独特性）
