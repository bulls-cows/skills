# yy-distill

## 描述

从用户指定的内容中分析并提炼能力模型，用于指导 AI agent 的通用行为/底层能力。涵盖感知能力、学习能力、推理能力、决策能力和其他能力五个维度。

**核心约束**：生成的能力描述必须是通用行为模式（能跨项目、跨 AI 模型复用）、具体可执行（能直接指导 AI agent 的决策和行为）、底层能力（而非特定项目的技能或操作）。

## 使用场景

- 用户想要分析感知能力和信息获取方式
- 用户想要识别学习能力和知识提取方式
- 用户想要挖掘推理能力和知识推断方式
- 用户想要理解决策能力和行动选择方式
- 用户想要提炼不属于上述四维的其他能力

不应触发：

- 用户只是查看内容
- 用户要求统计数量
- 用户要求分析其他人的内容（除非提供了该人的内容）
- 用户仅需要分析性格特质而非能力模型

## 指令

### 步骤 1. 确定分析来源

**必须要求用户提供分析来源**。

**决策分支**：

- **用户提供了来源**：直接进入步骤 2
- **用户未提供来源**：询问用户希望分析什么内容，等待用户回复后再进入步骤 2

可接受的内容形式：

- 文件路径（单个文件或目录）
- 文本内容（直接粘贴）
- URL（博客、文章等）
- 代码仓库

### 步骤 2. 五维能力信息采集

从以下五个维度分析能力模型：

#### 2.1 感知能力

分析获取和理解外部信息的方式：

- 信息获取：如何获取外部信息？主动探索还是被动接收？
- 信息理解：如何理解获取的信息？关注全局还是细节？
- 模式识别：能否从信息中发现规律和异常？
- 跨域感知：能否识别不同领域间的相似性？

#### 2.2 学习能力

分析从数据中提取知识和持续优化的方式：

- 知识提取：如何从数据/经验中提取知识？自上而下还是自下而上？
- 模式发现：能否发现数据中的模式、规律和关系？
- 知识迁移：如何将已有知识应用到新领域？
- 持续优化：如何不断改进和优化自身性能以适应新任务？

#### 2.3 推理能力

分析基于已有知识进行推断的方式：

- 推理方式：演绎、归纳、类比还是混合？
- 知识推断：如何根据已有知识推断未知结论？
- 假设构建：如何形成和验证假设？
- 因果分析：如何建立因果关系和排除干扰？

#### 2.4 决策能力

分析综合前三维结果做出决策和采取行动的方式：

- 决策依据：如何综合感知/学习/推理的结果做出决策？
- 方案选择：如何在多个选项中选择最优决策？
- 风险评估：如何评估和应对不确定性？
- 行动执行：如何将决策转化为具体行动？

#### 2.5 其他能力

分析不属于前四维的能力观察：

- 能力识别：是否存在无法归入感知/学习/推理/决策的能力特征？
- 独特特征：是否有独特的行为模式或偏好不属于前四维？
- 跨维能力：是否有能力特征横跨多个维度但又不属于任何一个？

### 步骤 3. 双重验证机制

对每个候选能力进行双重验证：

#### 验证1: 跨域一致性

能力是否在不同场景下稳定体现？

- 是 → 继续验证
- 否 → 降级为观察，不作为核心能力

#### 验证2: 有预测力

能否推断在新场景下的能力表现？

- 能 → 继续验证
- 不能 → 降级为描述，不作为预测性能力

**验证结果处理**：

- 双重通过 → 核心能力
- 一重通过 → 次要能力
- 零重通过 → 不纳入

### 步骤 4. 提炼能力模型

从能力角度提炼，而非操作层面。

#### 能力描述质量三重检验（重要）

对每条能力描述进行以下三重检验，确保它既通用又有实际价值：

**检验1：是否有具体判断标准**

- ✅ 好：有明确的判断标准，不是空话
- ❌ 坏：过于宽泛，无法判断何时适用

**检验2：是否能指导日常决策**

- ✅ 好：能用它来决定在具体场景下怎么做
- ❌ 坏：只是正面描述，没有指导意义

**检验3：是否跨场景适用**

- ✅ 好：不限于特定项目，能迁移到其他场景
- ❌ 坏：只能用于某个特定领域

**对比示例**：

| 类型     | ❌ 空泛描述                                                                        | ✅ 具体描述                                                                                            |
| -------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 感知能力 | **主动探索未知领域**：倾向于主动发现和探索未知，而非等待信息到来。                 | **隐性前提强制暴露**：在行动前将隐含的假设和决策分支强制暴露为可见规则，拒绝容忍模糊地带。             |
| 学习能力 | **自上而下构建认知框架**：习惯先建立整体结构，再填充细节，从顶层设计驱动具体实现。 | **多源交叉比对定位矛盾**：对同一信息的多个来源进行系统性比对，将零散差异归类为结构性矛盾而非孤立问题。 |
| 学习能力 | **通过类比迁移知识**：善于发现不同事物间的相似性，用已知模式理解新问题。           | **偏移回退而非修正**：检测到偏离时回退到原始定义，而非在偏移后的版本上修补。                           |
| 推理能力 | **假设先行验证跟进**：提出假设后先验证，确认成立再推进，而非直接执行。             | **逆向验证驱动**：从预期结果或期望行为反向推导规则是否合理，而非顺着规则正向核对。                     |
| 决策能力 | **追求一致性收敛**：倾向于统一标准、消除差异，向单一最优模式收敛。                 | **最小干预原则**：以"是否影响执行质量"为唯一筛选标准，克制改动冲动，只做必须做的事。                   |
| 决策能力 | **迭代优化逼近目标**：不追求一次性完美，通过持续小改进逐步接近理想状态。           | **目标闭环推进**：将任务转化为可验证目标，循环推进直到验证通过，强调"目标-执行-验证"闭环。             |
| 其他能力 | **偏好抽象而非具象**：倾向于从具体实例中提取抽象模式，而非停留在具体细节。         | **命名与层级对齐**：确保命名精确反映实际范围，且同一逻辑在不同呈现形式中层级一致。                     |
| 其他能力 | **重视可复现性**：强调过程的可追溯和结果的可复现，建立标准化流程。                 | **证据导向型决策**：每个决策都基于可追溯的证据链，而非主观偏好。                                       |

- **应该**：使用"隐性前提强制暴露""多源交叉比对定位矛盾""偏移回退而非修正"等能力描述
- **不要**：使用"DRY 原则践行者""代码写得好""主动探索未知领域"等操作、结果或空泛描述

提炼原则：

1. 每条能力用一句话概括，包含名称和具体表现
2. 基于内容证据，不做主观臆断
3. 从"如何感知/学习/推理/决策/其他"的角度理解，而非"做了什么"
4. **必须通过能力描述质量三重检验**

#### 避免套模板（重要）

**严禁照搬示例中的能力名称和描述**。示例仅供参考输出格式，能力内容必须从实际分析数据中提炼。

错误做法：

- 直接使用示例中的能力名称
- 套用示例中的证据描述
- 输出与示例高度相似的能力组合

正确做法：

- 从实际数据中识别独特的能力特征
- 用自己的语言命名和描述能力
- 确保证据来自分析内容，而非示例
- 如果分析结果与示例相似，应反思是否真正基于数据提炼

**自检方法**：输出前对照示例，检查能力名称是否雷同。如果超过一半的能力名称与示例相同，需要重新分析数据。

#### 隐私保护原则（重要）

输出结果必须遵循以下隐私保护原则：

1. **不引用原文**：不要直接引用或复述输入内容中的具体文本
2. **不暴露细节**：不要提及具体的文件名、代码片段、提交信息、人名、具体数值等
3. **抽象概括**：将具体行为抽象为一般性描述
4. **证据抽象化**：证据部分使用抽象化后的描述，而非原始内容

错误示例（暴露隐私）：

- "大量'移除'、'简化'、'删除'类提交"
- "如'移除未使用的导入'、'简化 lint 脚本逻辑'"
- "提交类型分布：feat (852)、refactor (549)"
- "主要贡献者：张三 (57%)、李四 (39%)"

正确示例（抽象概括）：

- "频繁进行代码简化相关的操作"
- "倾向于移除冗余代码和配置"
- "提交类型以功能开发和重构为主"
- "由少数核心贡献者主导"

### 步骤 5. 输出能力模型分析报告

按照以下结构输出分析结果：

#### 输出格式结构

- **感知能力**（必选）：感知维度下的核心能力
- **学习能力**（必选）：学习维度下的核心能力
- **推理能力**（必选）：推理维度下的核心能力
- **决策能力**（必选）：决策维度下的核心能力
- **其他能力**（必选）：无法归入前四维的能力观察

#### 能力描述格式

每个维度下的能力使用列表平铺，每项格式为：

- **能力名称**：一句话概括能力含义

示例（通用但具体的能力描述）：

- **隐性前提强制暴露**：在行动前将隐含的假设和决策分支强制暴露为可见规则，拒绝容忍模糊地带。
- **多源交叉比对定位矛盾**：对同一信息的多个来源进行系统性比对，将零散差异归类为结构性矛盾而非孤立问题。
- **偏移回退而非修正**：检测到偏离时回退到原始定义，而非在偏移后的版本上修补。
