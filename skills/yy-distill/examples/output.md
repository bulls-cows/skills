# 输出示例

以下是能力模型提炼的标准输出格式：

```markdown
## 能力模型分析报告

### 一、数据概览

- 总提交数：200+ 次
- 时间跨度：约 2 个月
- 代码变化：新增 2 万+ 行，删除 1 万+ 行，净增约 8 千行
- 活跃天数（日均提交≥10）：约 2 周，平均每日约 8 次提交

---

### 二、核心能力

#### 核心能力一：自上而下构建认知框架

**所属维度**：学习

**定义**：习惯先建立整体结构，再填充细节，从顶层设计驱动具体实现。

**证据**：

- 新建项目时先定义目录结构和规范，再编写具体代码
- 文档先有完整目录大纲，再逐步展开各章节内容
- 面对复杂问题时，先拆解为若干模块，再逐个处理

**验证**：

- 跨域一致性：✅ 在项目结构、文档组织、任务规划中均体现
- 有预测力：✅ 可推断在新问题上会先搭建框架再细化
- 有独特性：✅ 并非所有人都习惯从顶层开始构建

---

#### 核心能力二：假设先行验证跟进

**所属维度**：推理

**定义**：提出假设后先验证，确认成立再推进，而非直接执行。

**证据**：

- 代码变更前先写测试或原型验证可行性
- 文档结构调整前先在小范围验证效果
- 建立规范前先观察现有模式，验证合理性

**验证**：

- 跨域一致性：✅ 在代码、文档、流程设计中均体现验证思维
- 有预测力：✅ 可推断面对不确定情况会先假设后验证
- 有独特性：✅ 多数人倾向直接执行，而非先验证假设

---

#### 核心能力三：通过类比迁移知识

**所属维度**：学习

**定义**：善于发现不同事物间的相似性，用已知模式理解新问题。

**证据**：

- 新建技能时参考已有技能的结构和模式
- 将代码组织原则类比应用到文档组织
- 用熟悉的概念解释新的抽象概念

**验证**：

- 跨域一致性：✅ 在技能设计、文档编写、知识传递中均体现
- 有预测力：✅ 可推断面对新领域会寻找类比对象
- 有独特性：✅ 并非所有人都能灵活建立跨领域类比

---

#### 核心能力四：追求一致性收敛

**所属维度**：决策

**定义**：倾向于统一标准、消除差异，向单一最优模式收敛。

**证据**：

- 多次进行"对齐""统一""标准化"类操作
- 建立 lint 规则自动保持代码风格一致
- 文档格式向统一模板收敛

**验证**：

- 跨域一致性：✅ 在代码、文档、流程等多维度追求一致
- 有预测力：✅ 可推断面对分散模式会推动收敛统一
- 有独特性：✅ 并非所有人都有强烈的一致性追求

---

#### 核心能力五：迭代优化逼近目标

**所属维度**：决策

**定义**：不追求一次性完美，通过持续小改进逐步接近理想状态。

**证据**：

- 高频小粒度提交，而非大而全的一次性发布
- 同一技能或文档多次迭代优化
- 接受不完美的初始版本，后续持续改进

**验证**：

- 跨域一致性：✅ 在代码、文档、技能开发中均体现迭代思维
- 有预测力：✅ 可推断面对复杂问题会选择小步迭代
- 有独特性：✅ 多数人倾向追求完美版本，而非持续迭代

---

#### 核心能力六：主动探索未知领域

**所属维度**：感知

**定义**：倾向于主动发现和探索未知，而非等待信息到来。

**证据**：

- 主动建立工具和流程来发现潜在问题
- 在已有方案之外寻找更优解
- 关注边界情况和异常模式

**验证**：

- 跨域一致性：✅ 在代码质量、文档完整性、流程设计中均体现
- 有预测力：✅ 可推断面对新领域会主动探索而非被动等待
- 有独特性：✅ 多数人倾向在已知范围内工作

---

### 三、次要能力

#### 次要能力七：偏好抽象而非具象

**所属维度**：学习

**定义**：倾向于从具体实例中提取抽象模式，而非停留在具体细节。

**证据**：

- 将重复操作抽象为可复用的技能或脚本
- 用概念框架理解具体问题，而非就事论事
- 文档中大量使用抽象概念和模式描述

---

#### 次要能力八：重视可复现性

**所属维度**：决策

**定义**：强调过程的可追溯和结果的可复现，建立标准化流程。

**证据**：

- 建立技能使工作流程标准化、可复现
- 编写详细的验收清单和检查步骤
- 重视文档的完整性，便于他人复现

---

### 四、能力关联图谱

    主动探索未知领域
           │
           ▼
    自上而下构建认知框架
           │
           ▼
    追求一致性收敛 ──────► 迭代优化逼近目标 ◄────── 假设先行验证跟进
           │
           ▼
    通过类比迁移知识

**关联说明**：

- 主动探索为框架构建提供信息输入
- 自上而下构建框架为一致性收敛提供结构基础
- 一致性收敛通过迭代优化逐步实现
- 假设先行验证为迭代优化提供安全保障
- 通过类比迁移知识为框架构建提供参考

---

### 五、能力路径预测

基于以上能力模型，可预测在面对以下场景时的行为路径：

| 场景       | 预测行为路径                                                                              |
| ---------- | ----------------------------------------------------------------------------------------- |
| 新建项目   | 1. 主动探索相关领域 → 2. 先搭建整体框架和目录结构 → 3. 小步迭代填充内容 → 4. 持续对齐收敛 |
| 面对新问题 | 1. 寻找类比对象 → 2. 提出假设 → 3. 验证假设 → 4. 基于验证结果迭代优化                     |
| 发现不一致 | 1. 识别差异 → 2. 建立统一标准 → 3. 分阶段对齐 → 4. 验证一致性                             |
| 优化流程   | 1. 观察现有模式 → 2. 抽象出可复用模式 → 3. 建立标准化流程 → 4. 迭代改进                   |

---

### 六、总结

核心能力模型体现了一种**"感知驱动、框架构建、迭代优化"**的能力组合：

1. **主动感知**：主动探索未知，发现潜在问题
2. **框架学习**：从顶层设计出发，通过类比迁移知识
3. **验证推理**：通过假设-验证降低风险
4. **迭代决策**：小步快跑，逐步逼近目标，向最优模式收敛

这种能力模型适合从事需要长期维护、多人协作、持续演进的项目，能够在复杂度增长时保持系统的可维护性和一致性。
```
