# 能力描述质量参考

本文件提供能力描述的质量标准、对比示例和约束规则，供提炼能力时参考。

## 质量三重检验

对每条能力描述逐条检验：

- **有具体判断标准**：非空话，能判断何时适用
- **能指导日常决策**：能决定在具体场景下怎么做
- **跨场景适用**：不限于特定项目，能迁移

## 对比示例

### 空泛描述（应该避免）

- 感知能力：**主动探索未知领域**：倾向于主动发现和探索未知，而非等待信息到来。→ 太宽泛，无具体判断标准
- 学习能力：**自上而下构建认知框架**：习惯先建立整体结构，再填充细节，从顶层设计驱动具体实现。→ 描述方式，但无指导意义
- 学习能力：**通过类比迁移知识**：善于发现不同事物间的相似性，用已知模式理解新问题。→ 正确但空泛，无具体应用场景
- 推理能力：**假设先行验证跟进**：提出假设后先验证，确认成立再推进，而非直接执行。→ 流程描述，无思维模式深度
- 决策能力：**追求一致性收敛**：倾向于统一标准、消除差异，向单一最优模式收敛。→ 目标描述，无具体判断方法
- 决策能力：**迭代优化逼近目标**：不追求一次性完美，通过持续小改进逐步接近理想状态。→ 正确但空泛，人人都该这么做
- 其他能力：**偏好抽象而非具象**：倾向于从具体实例中提取抽象模式，而非停留在具体细节。→ 偏好描述，无行动指导
- 其他能力：**重视可复现性**：强调过程的可追溯和结果的可复现，建立标准化流程。→ 正确但空泛，无具体判断标准

### 具体描述（应该采用）

- 感知能力：**隐性前提强制暴露**：在行动前将隐含的假设和决策分支强制暴露为可见规则，拒绝容忍模糊地带。→ 有具体判断标准，能指导决策
- 学习能力：**多源交叉比对定位矛盾**：对同一信息的多个来源进行系统性比对，将零散差异归类为结构性矛盾而非孤立问题。→ 描述具体思维模式，可跨项目复用
- 学习能力：**偏移回退而非修正**：检测到偏离时回退到原始定义，而非在偏移后的版本上修补。→ 有明确的行动指导，能直接应用
- 推理能力：**逆向验证驱动**：从预期结果或期望行为反向推导规则是否合理，而非顺着规则正向核对。→ 描述独特的推理方法，有预测力
- 决策能力：**最小干预原则**：以"是否影响执行质量"为唯一筛选标准，克制改动冲动，只做必须做的事。→ 有具体判断标准，能指导日常决策
- 决策能力：**目标闭环推进**：将任务转化为可验证目标，循环推进直到验证通过，强调"目标-执行-验证"闭环。→ 描述完整流程，可直接复用
- 其他能力：**命名与层级对齐**：确保命名精确反映实际范围，且同一逻辑在不同呈现形式中层级一致。→ 有具体检查标准，可执行
- 其他能力：**证据导向型决策**：每个决策都基于可追溯的证据链，而非主观偏好。→ 描述决策原则，可跨场景应用

## 避免套模板

**严禁照搬上述示例中的能力名称和描述**。示例仅供参考输出格式，能力内容必须从实际分析数据中提炼。

错误做法：

- 直接使用示例中的能力名称
- 套用示例中的证据描述
- 输出与示例高度相似的能力组合

正确做法：

- 从实际数据中识别独特的能力特征
- 用自己的语言命名和描述能力
- 确保证据来自分析内容，而非示例
- 如果分析结果与示例相似，应反思是否真正基于数据提炼

**自检方法**：输出前对照示例，检查能力名称是否雷同。如果超过一半的能力名称与示例相同，需要重新分析数据。

## 隐私保护原则

输出结果必须遵循以下隐私保护原则：

1. **不引用原文**：不要直接引用或复述输入内容中的具体文本
2. **不暴露细节**：不要提及具体的文件名、代码片段、提交信息、人名、具体数值等
3. **抽象概括**：将具体行为抽象为一般性描述
4. **证据抽象化**：证据部分使用抽象化后的描述，而非原始内容

错误示例（暴露隐私）：

- "大量'移除'、'简化'、'删除'类提交"
- "如'移除未使用的导入'、'简化 lint 脚本逻辑'"
- "提交类型分布：feat (852)、refactor (549)"
- "主要贡献者：张三 (57%)、李四 (39%)"

正确示例（抽象概括）：

- "频繁进行代码简化相关的操作"
- "倾向于移除冗余代码和配置"
- "提交类型以功能开发和重构为主"
- "由少数核心贡献者主导"
