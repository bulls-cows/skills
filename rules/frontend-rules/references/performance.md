# ⚡ 性能优化规范

> 性能优化是前端开发的重要环节，直接影响用户体验。本规范从加载阶段、运行阶段、构建阶段三个维度，提供可落地的优化方案，确保应用流畅运行。
> 核心目标：首屏加载时间<2s，页面切换响应<100ms，滚动帧率>60fps。

---

---

## 🚀 一、加载阶段优化（核心影响首屏性能）

加载阶段优化目标是减少资源体积、减少请求数量、加快资源加载速度。

| 优化项          | 说明                                                                                  | 收益                    |
| --------------- | ------------------------------------------------------------------------------------- | ----------------------- |
| 路由懒加载      | 所有页面路由必须使用`() => import()`动态导入，禁止全量打包                            | 首屏包体积减少30%-70%   |
| 组件懒加载      | 大组件、非首屏组件使用动态导入，按需加载                                              | 减少页面初始加载资源    |
| 资源预加载      | 关键资源使用`<link rel="preload">`预加载，非关键资源使用`<link rel="prefetch">`预获取 | 提升资源加载优先级      |
| 图片优化        | 优先使用WebP/AVIF格式，合适尺寸，非首屏图片使用`loading="lazy"`懒加载                 | 图片体积减少50%以上     |
| 静态资源CDN     | 静态资源（图片、JS、CSS）部署到CDN，就近访问                                          | 加载速度提升200%-500%   |
| 缓存策略        | 静态资源设置强缓存（Cache-Control: max-age=31536000），HTML文件设置协商缓存           | 二次加载速度提升80%以上 |
| 按需引入依赖    | 第三方库按需引入，禁止全量导入，比如lodash-es按需导入函数，而不是全量导入             | 包体积减少20%-50%       |
| Gzip/Brotli压缩 | 所有静态资源开启Gzip或Brotli压缩                                                      | 文本资源体积减少60%-80% |
| 减少第三方依赖  | 优先使用原生API实现功能，避免引入不必要的第三方库                                     | 减少包体积              |
| 字体优化        | 字体文件使用woff2格式，子集化，按需加载，避免FOIT/FOUT                                | 字体加载速度提升        |

## ⚙️ 二、运行阶段优化（核心影响用户交互体验）

运行阶段优化目标是提升页面流畅度，减少卡顿，提升响应速度。

### 渲染性能优化

| 优化项             | 说明                                                                                                |
| ------------------ | --------------------------------------------------------------------------------------------------- |
| 虚拟滚动           | 长列表（100+项）必须使用虚拟滚动，仅渲染可视区域元素，避免DOM过多                                   |
| KeepAlive缓存      | 合理使用`<KeepAlive>`缓存不常更新的页面/组件，通过`include`/`exclude`精确控制缓存范围，避免内存泄漏 |
| 模板轻量化         | 模板只负责展示，不写复杂表达式与逻辑，复杂计算优先使用`computed`派生                                |
| 批量更新           | 批量修改响应式状态，避免多次触发重渲染                                                              |
| 冻结大数据         | 不需要响应式的大数据使用`Object.freeze()`冻结，取消响应式监听，减少内存占用                         |
| 避免不必要的重渲染 | 使用`memo`/`shallowRef`/`shallowReactive`优化响应式，避免不必要的更新                               |

### 交互性能优化

| 优化项         | 说明                                                                                                               |
| -------------- | ------------------------------------------------------------------------------------------------------------------ |
| 防抖节流       | 频繁触发的事件必须使用防抖/节流优化：搜索（防抖300ms）、滚动（节流100ms）、窗口resize（节流）、按钮点击（防抖/锁） |
| 避免阻塞主线程 | 耗时计算使用Web Worker异步处理，避免阻塞UI渲染                                                                     |
| 减少重排重绘   | 避免频繁修改DOM样式，优先使用transform和opacity做动画，触发GPU加速                                                 |
| 事件委托       | 大量元素的事件监听使用事件委托，减少事件绑定数量                                                                   |
| 内存泄漏防护   | 页面/组件卸载时必须清理定时器、事件监听、取消未完成的请求、关闭弹窗等                                              |
| 指令清理       | 自定义指令卸载钩子中必须清理事件监听器和定时器                                                                     |
| 路由守卫清理   | 路由离开前统一清理全局的定时器、请求、事件监听等                                                                   |

## 🏗️ 三、构建阶段优化（核心影响加载速度和运行性能）

构建阶段优化目标是减少打包体积、提升打包速度、优化产物质量。

| 优化项           | 说明                                                                    |
| ---------------- | ----------------------------------------------------------------------- |
| 代码分割         | 按路由、组件、第三方库分割代码，按需加载                                |
| Tree Shaking     | 开启Tree Shaking，移除未使用的代码，减少包体积                          |
| 压缩混淆         | 生产环境开启代码压缩混淆，移除console、debugger等调试信息               |
| 依赖分包         | 第三方依赖单独打包，利用浏览器缓存，避免频繁更新                        |
| 图片压缩         | 构建时自动压缩图片，减少图片体积                                        |
| 按需注入Polyfill | 按需注入Polyfill，只包含目标浏览器需要的兼容代码，避免全量引入          |
| Source Map优化   | 生产环境使用合适的Source Map，既方便调试又不暴露源码                    |
| 打包速度优化     | 使用SWC、esbuild等更快的构建工具，提升打包速度                          |
| 产物分析         | 定期使用打包分析工具（如webpack-bundle-analyzer）分析包体积，优化大依赖 |

## 🔍 四、性能检测与优化工具

| 工具                        | 用途                                                                            |
| --------------------------- | ------------------------------------------------------------------------------- |
| Chrome DevTools Performance | 分析页面运行时性能，找出卡顿原因                                                |
| Chrome DevTools Lighthouse  | 全面检测页面性能、可访问性、最佳实践等，给出优化建议                            |
| Web Vitals                  | 监控核心性能指标：LCP（最大内容绘制）、FID（首次输入延迟）、CLS（累积布局偏移） |
| 打包分析工具                | webpack-bundle-analyzer、rollup-plugin-visualizer等分析包体积，找出大依赖       |
| 性能埋点                    | 业务代码中添加性能埋点，监控真实用户的性能数据                                  |

## 📊 五、核心性能指标要求

| 指标                | 达标要求 | 优秀标准 |
| ------------------- | -------- | -------- |
| 首屏加载时间（FCP） | < 2s     | < 1s     |
| 最大内容绘制（LCP） | < 2.5s   | < 1.5s   |
| 首次输入延迟（FID） | < 100ms  | < 50ms   |
| 累积布局偏移（CLS） | < 0.1    | < 0.05   |
| 交互响应时间        | < 100ms  | < 50ms   |
| 页面帧率            | > 50fps  | > 60fps  |
